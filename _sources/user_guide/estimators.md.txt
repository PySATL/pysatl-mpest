# Выбор и настройка оценщика
**Назначение:** помочь выбрать между `EM`, `ECM` и `ECME` и настроить критерии остановки, удаление компонент и оптимизатор.

Примеры продолжают [быстрый старт](quickstart.md): используются его импорты, функция `show`, выборка `X` и начальная смесь `start`.

## Общие аргументы

Все три оценщика создаются с одними и теми же аргументами:

- `breakpointers` — {term}`критерии остановки <Критерий остановки>`. Оценка останавливается, когда срабатывает хотя бы один. Список не может быть пустым: иначе `fit` бросает `ValueError`.
- `pruners` — правила {term}`удаления компонент <Удаление компонент>`. Может быть пустым.
- `optimizer` — численный оптимизатор для параметров без решения в явном виде.

`fit(X, mixture)` принимает одномерную выборку и начальную смесь и возвращает оценённую смесь. Число компонент и их семейства задаёт начальная смесь: оценщик их не подбирает (кроме удаления компонент правилами `pruners`).

## Какой оценщик выбрать

| Оценщик | Что делает | Когда выбирать |
|---|---|---|
| `EM` | обновляет все свободные параметры компоненты за один шаг по {term}`Q-функции <Q-функция>` | по умолчанию |
| `ECM` | обновляет параметры компоненты группами по очереди, каждую группу — по Q-функции | совместная максимизация трудна, а по группам проще: меньше параметров на один вызов оптимизатора |
| `ECME` | для выбранных компонент максимизирует не Q-функцию, а само правдоподобие | нужно меньше итераций; шаг по правдоподобию всегда численный и дороже |

При мягком E-шаге и без удаления компонент все три алгоритма не уменьшают правдоподобие от итерации к итерации, если оптимизатор не возвращает точку хуже стартовой. У `ECME` есть ещё одна оговорка: он максимизирует логарифм правдоподобия, ограниченный снизу, и когда ограничение срабатывает, монотонность не гарантирована. Доказательства и оговорки — в разделе [EM-подобные алгоритмы](../math/algorithms/index.md).

### `ECM`: группы параметров

`parameter_groups` сопоставляет номеру компоненты упорядоченный список групп. Группы должны быть непустыми, не пересекаться и вместе покрывать все свободные параметры компоненты:

```python
from pysatl_mpest.estimators import ECM

ecm = ECM([LikelihoodBreakpointer(1e-6), StepBreakpointer(200)], [], ScipyNelderMead())
show(ecm.fit(X, start, parameter_groups={0: [{"sigma"}, {"mu"}]}))
print(round(ecm.history[0].mixture[0].parameters["sigma"], 3))

em.fit(X, start)
print(round(em.history[0].mixture[0].parameters["sigma"], 3))
```

```text
weight=0.405  {'mu': -0.052, 'sigma': 0.972}
weight=0.595  {'mu': 5.978, 'sigma': 1.495}
2.047
2.003
```

Здесь у компоненты 0 сначала обновляется `sigma`, затем `mu`; компонента 1 обновляется целиком, как в `EM`. Без `parameter_groups` `ECM` делает то же, что `EM`. Конечный результат в этом примере совпадает с `EM`, различается только путь итераций: после первой итерации `sigma` компоненты 0 у `ECM` равна 2.047, а у `EM` — 2.003. Причина в том, что `ECM` обновляет `sigma` при старом `mu`, а `EM` — при новом. Подробно пример для нормальной компоненты разобран на странице [ECM](../math/algorithms/ecm.md).

### `ECME`: выбор стратегии по компонентам

`ECME.fit` принимает номера компонент для каждой стратегии: `q_indices_raw` — шаги по Q-функции, `odl_indices_raw` — шаги по правдоподобию наблюдаемых данных. Остальные компоненты получают `default_strategy` из конструктора: `"odl"` (по умолчанию) или `"q-func"`. `parameter_groups` работает так же, как в `ECM`.

```python
from pysatl_mpest.estimators import ECME

ecme = ECME([LikelihoodBreakpointer(1e-6), StepBreakpointer(200)], [], ScipyNelderMead())
show(ecme.fit(X, start, q_indices_raw=[1]))
print(len(ecme.history))

show(ecme.fit(X, start))
print(len(ecme.history))
```

```text
weight=0.405  {'mu': -0.052, 'sigma': 0.972}
weight=0.595  {'mu': 5.978, 'sigma': 1.495}
11
weight=0.405  {'mu': -0.052, 'sigma': 0.972}
weight=0.595  {'mu': 5.978, 'sigma': 1.495}
6
```

Результат тот же, что у `EM`, но итераций меньше: 11, когда шаг по правдоподобию делает только компонента 0, и 6, когда его делают обе (у `EM` было 14). Каждая итерация при этом может быть дороже: у шага по правдоподобию нет решения в явном виде, его всегда ищет оптимизатор.

Компонента не может получить обе стратегии: если номер есть и в `q_indices_raw`, и в `odl_indices_raw`, `fit` бросает `ValueError`.

## Критерии остановки

- `StepBreakpointer(max_steps)` останавливает оценку после `max_steps` итераций.
- `LikelihoodBreakpointer(threshold)` останавливает оценку, когда логарифм правдоподобия за итерацию меняется меньше чем на `threshold`.

Обычно их задают вместе, как в примерах: `LikelihoodBreakpointer` останавливает сошедшуюся оценку, `StepBreakpointer` ограничивает время, если сходимость медленная.

## Удаление компонент

`PriorThresholdPruner(threshold)` удаляет компоненты, вес которых упал ниже `threshold`, и перенормирует веса остальных. Хотя бы одна компонента всегда остаётся. Правило полезно, когда число компонент задано с запасом:

```python
from pysatl_mpest.estimators.iterative import PriorThresholdPruner

extra = MixtureModel([normal(mu=0.0, sigma=2.0), normal(mu=5.0, sigma=2.0), normal(mu=20.0, sigma=1.0)])
em_pruning = EM([LikelihoodBreakpointer(1e-6), StepBreakpointer(200)], [PriorThresholdPruner(0.05)], ScipyNelderMead())
show(em_pruning.fit(X, extra))
```

```text
weight=0.405  {'mu': -0.052, 'sigma': 0.972}
weight=0.595  {'mu': 5.978, 'sigma': 1.495}
```

Компонента с центром 20 далеко от данных, её вес на первой же итерации падает ниже 0.05, и она удаляется. На итерации с удалением правдоподобие может уменьшиться.

## Оптимизатор

`ScipyNelderMead` и `ScipyPowell` вызывают `scipy.optimize.minimize` с методами Nelder–Mead и Powell. Оптимизатор используется только там, где нет решения в явном виде: в шагах по правдоподобию `ECME` и в шагах по Q-функции для семейств и параметризаций, кроме (`Normal`, `meanStd`) и (`Exponential`, `rate`).

Выбирайте `ScipyNelderMead`, если важна монотонность: он никогда не возвращает точку хуже стартовой, и на этом держатся гарантии роста правдоподобия. Для `ScipyPowell` это не проверено.

## Свой конвейер

Оценщики — фасады над `Pipeline`. Если нужна комбинация шагов, которой нет в фасадах, конвейер собирают вручную. Например, стратегия `MOMENTS` (метод моментов вместо максимизации) доступна только так:

```python
from pysatl_mpest.estimators.iterative import (
    ExpectationStep,
    MaximizationStep,
    MaximizationStrategy,
    OptimizationBlock,
    Pipeline,
    WeightsStep,
)

blocks = [OptimizationBlock(j, None, MaximizationStrategy.MOMENTS) for j in range(start.n_components)]
pipeline = Pipeline(
    [ExpectationStep(), WeightsStep(), MaximizationStep(blocks, ScipyNelderMead())],
    [LikelihoodBreakpointer(1e-6), StepBreakpointer(200)],
)
show(pipeline.fit(X, start))
```

```text
weight=0.405  {'mu': -0.052, 'sigma': 0.972}
weight=0.595  {'mu': 5.978, 'sigma': 1.495}
```

У метода моментов нет гарантии роста правдоподобия; подробности — на странице [`moments`](../math/strategies/moments.md).

Так же собирается конвейер с {term}`жёстким E-шагом <Жёсткий E-шаг>`: вместо `ExpectationStep()` передаётся `ExpectationStep(is_soft=False)`. Готовые оценщики используют только мягкий E-шаг. Как устроен конвейер и как добавить свой шаг — на странице модуля [`iterative`](../design/modules/estimators/iterative/iterative.md).
