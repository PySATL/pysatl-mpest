## Общая схема

Все три алгоритма чередуют два шага. {term}`E-шаг <E-шаг>` по текущим параметрам вычисляет {term}`ответственности <Ответственность>` {eq}`eq-responsibilities` и тем самым {term}`Q-функцию <Q-функция>` {eq}`eq-q-function`. {term}`M-шаг <M-шаг>` выбирает новые параметры. Алгоритмы отличаются только M-шагом:

| Алгоритм | M-шаг | Оценщик | Блоки оптимизации | Источник |
|---|---|---|---|---|
| [EM](em.md) | максимизация $Q$ сразу по всем параметрам компоненты | `EM` | один блок на компоненту, стратегия `QFUNCTION` | {footcite:t}`dempster1977em` |
| [ECM](ecm.md) | последовательность {term}`CM-шагов <CM-шаг>`: максимизация $Q$ по группе параметров при фиксированных остальных | `ECM` | блок на каждую группу из `parameter_groups`, стратегия `QFUNCTION` | {footcite:t}`meng1993ecm` |
| [ECME](ecme.md) | часть CM-шагов максимизирует не $Q$, а {term}`правдоподобие наблюдаемых данных <Правдоподобие наблюдаемых данных>` | `ECME` | блоки как у `ECM`, стратегия `QFUNCTION` или `OBSERVED_DATA_LIKELIHOOD` для каждой компоненты | {footcite:t}`liu1994ecme` |

Монотонность правдоподобия у EM и ECM выводится из одного результата: если M-шаг не уменьшает Q-функцию, то не уменьшается и правдоподобие. Этот результат и понятие {term}`обобщённого EM <Обобщённый EM>` разобраны на странице [EM](em.md). ECME нужен отдельный аргумент: его шаги по правдоподобию наблюдаемых данных не обязаны увеличивать Q-функцию, и монотонность зависит от порядка шагов. Он разобран на странице [ECME](ecme.md).

## Цикл конвейера

Оценщики `EM`, `ECM` и `ECME` собирают один и тот же конвейер `Pipeline` из шагов `ExpectationStep`, `WeightsStep` и `MaximizationStep` и отличаются только списком блоков, который получает `MaximizationStep`. Одна итерация `Pipeline.fit` выполняется в таком порядке:

1. `ExpectationStep` вычисляет матрицу ответственностей `state.H`.
2. `WeightsStep` обновляет веса по `state.H`.
3. `MaximizationStep` обновляет параметры компонент по блокам; все блоки итерации используют одну и ту же `state.H`.
4. Правила {term}`удаления компонент <Удаление компонент>` (`pruners`) убирают компоненты.
5. Состояние записывается в историю итераций.
6. {term}`Критерии остановки <Критерий остановки>` (`breakpointers`) решают, нужна ли следующая итерация.

Последовательность вызовов при `fit` показана в разделе [Поведение](../../design/behavior.md).
