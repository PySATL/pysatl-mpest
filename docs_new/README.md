# docs_new

Новая документация pysatl-mpest. До переключения собирается отдельно от `docs/` и не участвует в CI.

```bash
poetry run sphinx-build -W --keep-going -n -b html docs_new/source docs_new/build/html
poetry run python docs_new/tools/export_diagrams.py   # PNG из всех листов .drawio
```

## Диаграммы

- Источник — `.drawio`, внутри листы; PNG каждого листа лежит рядом: `<файл>.<id листа>.png`. PNG не правится руками, только экспортом (`tools/export_diagrams.py`; нужен draw.io CLI 27.0.2+). Правка диаграммы и обновление PNG — один коммит.
- Диаграммы лежат в `diagrams/` рядом с документом, который их объясняет. Верхний уровень — `source/design/diagrams/`, модуль — `source/design/modules/<модуль>/diagrams/<модуль>.drawio`.
- Id листа — kebab-case, имя листа — по-английски. Листы модуля идут в порядке: `overview`, `packages`, страницы подмодулей, затем `seq-*` (sequence). Верхнеуровневые: `full-architecture` (`system-context`), `module-architecture` (`overview`, `detailed`), `usecases`, `sequences` (`seq-*`), `activity`, `algorithms-tree`.
- **Диаграмма должна помещаться в страницу документации:** ширина листа не больше ~900 px, высота не больше ~650 px (в границах всех блоков, включая заголовок и легенду), шрифт на блоках не мельче 11 pt. Если не влезает, диаграмма делится на несколько листов, а не уменьшается. Размер проверяется по PNG.
- Без пояснительного текста на диаграммах: только заголовок, имена элементов (как в коде) и подписи связей там, где без них не понять; пояснения идут в md. Статус элемента (planned, external) передаётся стилем и легендой, а не словом в блоке.
- Подписи на диаграммах английские. Имена классов и модулей пишутся как в коде.
- Диаграмма показывает код как он есть. Модули, которых ещё нет в коде, рисуются стилем *planned*: пунктирная рамка `dashed=1`, серые обводка и текст `#666666`, белая заливка.
- Стиль: чёрно-белый, `Helvetica`; обычный блок — белая заливка и чёрная обводка 1.5; внешняя зависимость (`pysatl-core`, `numpy`, `scipy`) — заливка `#F2F2F2`. Зависимость `A → B` («A использует B») — пунктирная стрелка, наследование — сплошная с полым треугольником. Заголовок листа — текстовая ячейка слева сверху, 18 pt, жирный.
- На странице документа рядом с PNG даётся ссылка на исходник с названиями листов в title: `[схема](diagrams/core.drawio "Overview, Packages")`. Расширение `source/_ext/drawio_viewer.py` вставляет после абзаца интерактивный viewer diagrams.net на каждом из перечисленных листов (названия листов — как в файле). В тёмной теме `source/_static/drawio-viewer.css` инвертирует цвета, поэтому диаграммы строго чёрно-белые, без цветных заливок.
- Просмотр изменений: `DRAWIO_DIFF_NO_OPEN=1 git drawiodiff [<коммит>] -- <файл>.drawio`.

## Текст

- Страница: `# Заголовок`, затем строка `**Назначение:** …`; один H1, заголовки без скачков; абзац — одна строка; ссылки — относительные.
- Текст русский; имена классов, модулей и параметров — как в коде, в обратных кавычках.
- Страница модуля: назначение, листы диаграммы (PNG и ссылка на `.drawio`), классы по коду, ограничения. Подробности сигнатур не дублируются: их генерирует `source/api/`.
- Описывается только то, что есть в коде; планируемое помечается «Запланировано».
