Модель смеси#

Назначение: ввести обозначения и величины, на которых строятся все алгоритмы библиотеки: плотность смеси, правдоподобие, апостериорные вероятности принадлежности компонентам и Q-функцию, а также показать, где каждая из них вычисляется в коде.

Обозначения#

Выборка состоит из независимых одинаково распределённых наблюдений. Индексы на всех страницах раздела означают одно и то же:

  • \(i = 1, \dots, n\) — номер наблюдения;

  • \(j = 1, \dots, k\) — номер компоненты смеси;

  • верхний индекс \((t)\) — номер итерации алгоритма.

Плотность смеси#

Определение 1 (Конечная смесь распределений)

Плотность конечной смеси из \(k\) компонент равна

(1)#\[ f(x \mid \Psi) = \sum_{j=1}^{k} \omega_j \, f_j(x \mid \theta_j), \]

где веса неотрицательны и в сумме дают единицу:

\[ \omega_j \ge 0, \qquad \sum_{j=1}^{k} \omega_j = 1. \]

Компоненты не обязаны принадлежать одному семейству: в MixtureModel можно сложить, например, нормальное и экспоненциальное распределения.

Веса хранятся в виде логарифмов, а MixtureModel.lpdf считает логарифм плотности (1) так:

\[ \ln f(x \mid \Psi) = \operatorname{logsumexp}_{j} \bigl(\ln \omega_j + \ln f_j(x \mid \theta_j)\bigr). \]

Так сумма малых плотностей не обнуляется в арифметике с плавающей точкой.

Правдоподобие наблюдаемых данных#

Наблюдения независимы, поэтому правдоподобие смеси по выборке — произведение плотностей (1), а его логарифм — сумма:

(2)#\[ \ln L(\Psi \mid x) = \sum_{i=1}^{n} \ln \sum_{j=1}^{k} \omega_j \, f_j(x_i \mid \theta_j). \]

Оценка максимального правдоподобия — параметры, при которых (2) максимально. Найти их напрямую трудно. Логарифм стоит перед суммой по компонентам, поэтому (2) не распадается на слагаемые по отдельным компонентам, и условие экстремума по параметрам одной компоненты зависит от параметров всех остальных.

В коде (2) считает MixtureModel.loglikelihood. Это же значение записывается в историю итераций и проверяется критериями остановки по правдоподобию.

Скрытые переменные и полные данные#

EM-подход [1] дополняет каждое наблюдение ненаблюдаемой меткой — номером компоненты, которая его породила. Метку записывают индикаторами:

\[\begin{split} z_{ij} = \begin{cases} 1, & \text{если наблюдение } x_i \text{ порождено компонентой } j, \\ 0, & \text{иначе.} \end{cases} \end{split}\]

В каждой строке ровно один индикатор равен единице. Вероятность того, что наблюдение порождено компонентой \(j\), равна её весу:

\[ P(z_{ij} = 1) = \omega_j. \]

Выборку вместе с метками называют полными данными. Если бы метки были известны, в правдоподобие полных данных входили бы только сомножители, у которых индикатор равен единице:

\[ L_c(\Psi \mid x, z) = \prod_{i=1}^{n} \prod_{j=1}^{k} \bigl(\omega_j \, f_j(x_i \mid \theta_j)\bigr)^{z_{ij}}. \]

Его логарифм уже не содержит логарифма суммы [2], формула (2.26):

(3)#\[ \ln L_c(\Psi \mid x, z) = \sum_{i=1}^{n} \sum_{j=1}^{k} z_{ij} \bigl(\ln \omega_j + \ln f_j(x_i \mid \theta_j)\bigr). \]

Апостериорные вероятности#

Метки неизвестны. Обозначим через \(Z_{ij}\) случайные величины, значения которых — индикаторы \(z_{ij}\), и заменим каждый индикатор условным математическим ожиданием при текущих параметрах. Так как \(Z_{ij}\) принимает только значения 0 и 1, её условное ожидание равно вероятности единицы. По формуле Байеса эта вероятность равна

(4)#\[ \gamma_{ij}^{(t)} = \mathbb{E}\bigl[Z_{ij} \mid x, \Psi^{(t)}\bigr] = P\bigl(Z_{ij} = 1 \mid x_i, \Psi^{(t)}\bigr) = \frac{\omega_j^{(t)} \, f_j(x_i \mid \theta_j^{(t)})}{\sum_{l=1}^{k} \omega_l^{(t)} \, f_l(x_i \mid \theta_l^{(t)})}. \]

Та же формула для произвольных параметров \(\Psi\) вместо \(\Psi^{(t)}\) задаёт \(\gamma_{ij}(\Psi)\), так что \(\gamma_{ij}^{(t)} = \gamma_{ij}(\Psi^{(t)})\).

Матрицу ответственностей размера \(n \times k\) на E-шаге вычисляет ExpectationStep и записывает в state.H. Числитель и знаменатель (4) считаются в логарифмах: из каждой строки логарифмов взвешенных плотностей вычитается её logsumexp, и результат возводится в экспоненту.

У этого вычисления есть две особенности, которых нет в формуле:

  • Если наблюдение лежит вне носителя всех компонент, знаменатель (4) равен нулю. Такая строка state.H заполняется нулями и в сумме не даёт единицу, поэтому наблюдение не влияет на M-шаг.

  • При ExpectationStep(is_soft=False) (жёсткий E-шаг) каждая строка заменяется индикатором компоненты с наибольшей ответственностью: наблюдение целиком относится к одной компоненте вместо распределения по всем.

Q-функция#

Подставим ответственности вместо неизвестных индикаторов в логарифм правдоподобия полных данных (3). Формально это математическое ожидание (3) по распределению меток при текущих параметрах.

Определение 2 (Q-функция)

\[ Q(\Psi \mid \Psi^{(t)}) = \mathbb{E}_{Z \mid x, \Psi^{(t)}}\bigl[\ln L_c(\Psi \mid x, Z)\bigr]. \]

Логарифм правдоподобия полных данных (3) линеен по \(Z_{ij}\). Поэтому математическое ожидание проходит внутрь суммы и заменяет каждую \(Z_{ij}\) ответственностью (4) [2], формула (2.27):

(5)#\[ Q(\Psi \mid \Psi^{(t)}) = \sum_{i=1}^{n} \sum_{j=1}^{k} \gamma_{ij}^{(t)} \bigl(\ln \omega_j + \ln f_j(x_i \mid \theta_j)\bigr). \]

В отличие от (2), в (5) нет логарифма суммы. Ответственности фиксированы на текущей итерации, а параметры входят в отдельные слагаемые. На этом свойстве строятся M-шаги библиотеки. Связь между ростом Q-функции и ростом правдоподобия (2) доказали Dempster et al.[1].
