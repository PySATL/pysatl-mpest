ECME#

Назначение: описать, как ECME заменяет часть CM-шагов ECM шагами по правдоподобию наблюдаемых данных, доказать, что итерация остаётся монотонной при порядке шагов из оценщика ECME, и объяснить, как этот порядок устроен в коде.

Идея#

CM-шаг ECM (12) максимизирует \(Q(\cdot \mid \Psi^{(t)})\) — приближение к правдоподобию, построенное в точке \(\Psi^{(t)}\). ECME [1] позволяет на части CM-шагов максимизировать при тех же ограничениях само правдоподобие наблюдаемых данных (2). Такой шаг не опирается на ответственности \(\gamma^{(t)}\) и поэтому не «помнит» параметры с итерации \(t\). По этой причине ECME обычно сходится за меньшее число итераций, чем EM и ECM [1]. Цена — сложнее задача шага: у неё почти никогда нет решения в явном виде.

Итерация#

Шаги, которые максимизируют \(Q(\cdot \mid \Psi^{(t)})\), назовём Q-шагами, а шаги, которые максимизируют \(\ln L\), — L-шагами. Параметры \(j\)-й компоненты разбиты на группы \(\theta_j^{[1]}, \dots, \theta_j^{[S_j]}\), как в ECM. Каждой компоненте назначен один вид шагов: множество \(\mathcal{J}_Q\) компонент с Q-шагами и множество \(\mathcal{J}_L\) компонент с L-шагами не пересекаются и вместе дают \(\{1, \dots, k\}\).

Итерация \(t \to t + 1\) состоит из таких шагов:

  1. E-шаг. Как в EM: по \(\Psi^{(t)}\) вычисляются ответственности (4).

  2. Q-шаг для весов. Веса обновляются по (9), как в EM и ECM.

  3. Q-шаги. Для каждой компоненты \(j \in \mathcal{J}_Q\) по порядку групп выполняются CM-шаги (12).

  4. L-шаги. Для каждой компоненты \(q \in \mathcal{J}_L\) по порядку групп \(s = 1, \dots, S_q\):

(14)#\[ \theta_q^{[s]} \leftarrow \arg\max_{\theta_q^{[s]}} \ln L(\Psi \mid x), \]

где все параметры \(\Psi\), кроме группы \(\theta_q^{[s]}\), фиксированы на последних известных значениях. Это задача стратегии observed_data_likelihood (18).

Все Q-шаги стоят раньше всех L-шагов. В общем определении ECME [1] порядок шагов не ограничен, но доказательство монотонности ниже работает только для такого порядка.

Свойства#

Theorem 4 (Монотонность ECME)

Пусть в итерации ECME все Q-шаги, включая шаг для весов, выполняются раньше всех L-шагов, каждый Q-шаг не уменьшает \(Q(\cdot \mid \Psi^{(t)})\), а каждый L-шаг не уменьшает \(\ln L\). Тогда

\[ \ln L(\Psi^{(t+1)} \mid x) \ge \ln L(\Psi^{(t)} \mid x). \]

Proof. Пусть итерация состоит из \(C\) шагов, первые \(C_Q\) из них — Q-шаги, и \(\Psi^{(t, c)}\) — параметры после \(c\)-го шага:

\[ \Psi^{(t, 0)} = \Psi^{(t)}, \qquad \Psi^{(t, C)} = \Psi^{(t+1)}. \]

Q-шаги. Каждый Q-шаг не уменьшает \(Q(\cdot \mid \Psi^{(t)})\), поэтому, как в доказательстве теоремы Theorem 3,

\[ Q(\Psi^{(t, C_Q)} \mid \Psi^{(t)}) \ge Q(\Psi^{(t)} \mid \Psi^{(t)}). \]

Доказательство теоремы Theorem 1 использует только это неравенство между точкой и \(\Psi^{(t)}\), поэтому

\[ \ln L(\Psi^{(t, C_Q)} \mid x) \ge \ln L(\Psi^{(t)} \mid x). \]

L-шаги. Каждый L-шаг максимизирует \(\ln L\) по группе параметров, а текущее значение группы — допустимая точка, поэтому

\[ \ln L(\Psi^{(t, c)} \mid x) \ge \ln L(\Psi^{(t, c-1)} \mid x), \qquad c = C_Q + 1, \dots, C. \]

Объединяя неравенства, получаем

\[ \ln L(\Psi^{(t+1)} \mid x) \ge \ln L(\Psi^{(t, C_Q)} \mid x) \ge \ln L(\Psi^{(t)} \mid x). \]

Почему важен порядок#

Liu and Rubin[1] доказывают монотонность одной строкой: Q-шаги увеличивают \(Q\), а значит и \(\ln L\), L-шаги увеличивают \(\ln L\) по определению. Первая часть верна, только пока все предыдущие шаги итерации — Q-шаги.

Пусть шаг \(c\) — L-шаг, а шаг \(c + 1\) — Q-шаг. По тождеству (11)

\[ \ln L(\Psi^{(t, c+1)} \mid x) - \ln L(\Psi^{(t, c)} \mid x) = \underbrace{\bigl[Q(\Psi^{(t, c+1)} \mid \Psi^{(t)}) - Q(\Psi^{(t, c)} \mid \Psi^{(t)})\bigr]}_{\ge 0} - \bigl[R(\Psi^{(t, c+1)} \mid \Psi^{(t)}) - R(\Psi^{(t, c)} \mid \Psi^{(t)})\bigr]. \]

Неравенство Гиббса ограничивает \(R(\cdot \mid \Psi^{(t)})\) сверху только значением в точке \(\Psi^{(t)}\), а не в \(\Psi^{(t, c)}\). Поэтому вторая скобка может быть положительной, и рассуждение не даёт \(\ln L(\Psi^{(t, c+1)}) \ge \ln L(\Psi^{(t, c)})\). Не помогает и сравнение с \(\Psi^{(t)}\): L-шаг мог уменьшить \(Q(\cdot \mid \Psi^{(t)})\), и тогда неизвестно даже, что \(Q(\Psi^{(t, c+1)} \mid \Psi^{(t)}) \ge Q(\Psi^{(t)} \mid \Psi^{(t)})\).

Чтобы Q-шаг после L-шага сохранял монотонность, перед ним нужен новый E-шаг в точке \(\Psi^{(t, c)}\). Так устроен алгоритм AECM [2]: итерация делится на циклы, каждый цикл начинается своим E-шагом и является итерацией GEM. ECME с порядком «Q-шаги, затем L-шаги» укладывается в эту схему из двух циклов: в первом скрытые данные — метки компонент, во втором скрытых данных нет и \(Q = \ln L\).

Сходимость#

Liu and Rubin[1] переносят на ECME теорему о сходимости ECM [3]. Её условия — условия теоремы Theorem 2 и два дополнительных:

  1. ограничения CM-шагов «заполняют пространство»: вместе шаги одной итерации позволяют сдвинуть любой параметр;

  2. максимум в каждом CM-шаге единственный.

При этих условиях все предельные точки последовательности ECME — стационарные точки правдоподобия, и \(\ln L(\Psi^{(t)} \mid x)\) монотонно сходится к значению в одной из них. Доказательство опирается на равенство градиентов \(Q(\cdot \mid \Psi^{(t)})\) и \(\ln L\) в точке \(\Psi^{(t)}\) и здесь не повторяется.

Первое условие в коде выполнено: группы каждой компоненты покрывают все её свободные параметры, а веса обновляет WeightsStep. Второе условие и компактность не проверяются; что из этого следует для смесей, разобрано после теоремы Theorem 2.

L-шаг (14)

блок со стратегией OBSERVED_DATA_LIKELIHOOD

порядок «Q-шаги, затем L-шаги»

сортировка блоков в ECME.fit

ECME.fit строит блоки функцией build_optimization_blocks, как ECM, а затем устойчиво сортирует их так, что все блоки QFUNCTION идут раньше всех блоков OBSERVED_DATA_LIKELIHOOD. Внутри каждой части сохраняется порядок компонент и групп. Именно эта сортировка выполняет условие теоремы Theorem 4. Компонента не может получить оба вида шагов: если индекс есть и в q_indices_raw, и в odl_indices_raw, fit бросает ValueError.

MaximizationStep выполняет блоки QFUNCTION разных компонент в одной волне, а каждый блок OBSERVED_DATA_LIKELIHOOD — в отдельной волне после них: он читает все компоненты, включая результаты предыдущих блоков (см. Волны M-шага). Поэтому каждый L-шаг видит параметры после всех предыдущих шагов итерации, как в (14).

При значении по умолчанию default_strategy="odl" и без q_indices_raw все компоненты получают L-шаги. Тогда единственный Q-шаг итерации — обновление весов, а остальная итерация — покоординатный подъём по \(\ln L\).

Отступления от теории#

Для Q-шагов верны оговорки EM из раздела Отступления от теории: численный шаг должен не ухудшать стартовую точку, а жёсткий E-шаг и удаление компонент выводят итерацию за рамки теоремы. Для L-шагов добавляются две.

Численный L-шаг. Решения (14) в явном виде в библиотеке нет, его всегда ищет optimizer, начиная с текущих значений. Шаг не уменьшает \(\ln L\), только если оптимизатор не возвращает точку хуже стартовой; для ScipyNelderMead это выполняется.

Ограничение логарифма снизу. Стратегия максимизирует не \(\ln L\), а (20). Пока ограничение не срабатывает ни в одной точке, это одно и то же; когда срабатывает, рост целевой функции не гарантирует роста \(\ln L\). Подробно — в разделе Монотонность шага.
