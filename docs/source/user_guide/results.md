# Результат и история
**Назначение:** показать, как читать историю итераций, что происходит при ошибке и какие проблемы оценки встречаются чаще всего.

Примеры продолжают [быстрый старт](quickstart.md): используются его импорты, выборка `X`, начальная смесь `start` и оценщик `em`.

## История итераций

После `fit` у оценщика есть свойство `history`. До первого `fit` обращение к нему бросает `AttributeError`. Каждый следующий `fit` того же оценщика заменяет историю.

История — последовательность записей `IterationRecord`: она поддерживает `len` и доступ по индексу, в том числе отрицательному (`history[-1]`). Классы истории и записи не экспортируются публично, поэтому в [справочнике API](../api/index.rst) их нет. Поля записи:

- `iteration` — номер итерации, начиная с 0;
- `mixture` — смесь после итерации, включая удаление компонент;
- `X` — выборка;
- `H` — матрица ответственностей размера «число наблюдений × число компонент»;
- `pruners_used` — список правил удаления, заданных оценщику; он не показывает, удалило ли правило компоненту, а у записи, созданной из-за ошибки до первой сохранённой итерации, равен `None`;
- `error` — исключение, если оценка остановилась с ошибкой, иначе `None`.

Что важно учитывать при чтении истории:

- `H` записи — ответственности, которые E-шаг этой итерации вычислил по смеси **до** M-шага. По ним обновлялись веса и параметры, поэтому они не соответствуют `mixture` той же записи.
- Исходной смеси в истории нет: `history[0].mixture` — смесь уже после первой итерации.
- Если последняя итерация не попала в историю (см. `once_in_iterations` ниже), `history[-1].mixture` не совпадает с результатом `fit`. Результат берите из возвращаемого значения.

Например, рост правдоподобия по итерациям:

```python
em.fit(X, start)
history = em.history
values = [history[i].mixture.loglikelihood(X) for i in range(len(history))]
print(round(values[0], 1), round(values[-1], 1))
```

```text
-4965.8 -4603.7
```

Чтобы не хранить каждую итерацию, `fit` принимает `once_in_iterations`: при `once_in_iterations=5` записываются итерации 0, 5, 10 и так далее. В примере выше оценка заняла 14 итераций, и последней в истории окажется итерация 10.

## Ошибки во время оценки

Исключение, брошенное шагом конвейера, вылетает из `fit` как обычно. Например, стратегия `MOMENTS` бросает `NotImplementedError` для семейства, которое она не поддерживает.

Шаг может и не бросать исключение, а записать ошибку в `state.error`. Тогда `fit` останавливается без исключения: выдаёт `RuntimeWarning`, возвращает смесь на момент ошибки и записывает исключение в `error` последней записи истории. Встроенные шаги делают так, только когда им не хватает входных данных, например E-шаг не вычислил `H`. В штатных оценщиках этого не бывает, но в собственном конвейере (`Pipeline`) возможно, поэтому после `fit` полезно проверить:

```python
if em.history[-1].error is not None:
    raise em.history[-1].error
```

Ошибки конфигурации — неверный номер компоненты, неизвестный или фиксированный параметр в `parameter_groups`, одна компонента в обоих списках `ECME` — проверяются до начала итераций и бросают `ValueError` сразу.

## Типичные проблемы

**Сошлась ли оценка.** Если оценка остановилась по `StepBreakpointer`, а не по `LikelihoodBreakpointer`, правдоподобие ещё менялось и результат может быть далёк от стационарной точки. При `once_in_iterations=1` это видно по длине истории: `len(em.history) < max_steps` означает, что сработал `LikelihoodBreakpointer`. Если лимит исчерпан, увеличьте `max_steps` или возьмите другую начальную смесь.

**Результат зависит от начальной смеси.** Алгоритмы находят стационарную точку правдоподобия, которая может быть локальным максимумом. Автоматического подбора начального приближения пока нет, начальную смесь задаёт пользователь. Разумная начальная смесь строится по виду выборки: центры компонент — в районе пиков гистограммы, масштабы — порядка ширины пиков, веса — равные. Если оценки выглядят неправдоподобно, запустите `fit` из нескольких начальных смесей и сравните `loglikelihood(X)` результатов.

**Вырождение.** Правдоподобие смеси нормальных распределений неограниченно: компонента может «сесть» на одно наблюдение с $\sigma \to 0$. Явные формулы M-шага в таких случаях оставляют параметры прежними, но при численной оптимизации и неудачной начальной смеси вырождение возможно. Подробнее — в разделе о [сходимости EM](../math/algorithms/em.md).

**Наблюдения вне носителя.** Если наблюдение не попадает в носитель ни одной компоненты, например отрицательное значение при смеси экспоненциальных распределений, его ответственности нулевые, и оно молча исключается из оценки весов и из критерия `LikelihoodBreakpointer`. Предупреждения при этом нет, а `mixture.loglikelihood(X)` такой выборки равен $-\infty$. Проверяйте, что начальная смесь покрывает все данные.

**Удаление компонент меняет правдоподобие.** На итерации, где `PriorThresholdPruner` удалил компоненту, правдоподобие может уменьшиться. Где это произошло, видно по `mixture.n_components` соседних записей истории.
