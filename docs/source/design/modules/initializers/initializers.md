## Задача

Инициализатор получает выборку `X` и список `families`, по элементу на компоненту, и возвращает `MixtureModel` с полностью заданными параметрами и весами. Результат передаётся в `fit` оценщиков смеси из `estimators`.

```python
normal = ParametricFamilyRegister.get(FamilyName.NORMAL)
expon = ParametricFamilyRegister.get(FamilyName.EXPONENTIAL)

initializer = ClusterInitializer(KMeansAssigner())
start = MultiStartInitializer(initializer, n_init=10).initialize(X, [normal, normal, expon], random_state=42)
result = EM(...).fit(X, start)
```

Слово «оценщик» в этом документе всегда уточняется:

- **оценщик смеси** — `EM`, `ECM`, `ECME` из `estimators`, оценивают всю смесь;
- **оценщик компоненты** — `ComponentEstimator` и его реализации в `initializers`, оценивают параметры одной компоненты по кластеру.

### Вход: `families`

- Элемент `families` — `ParametricFamily` из `pysatl-core`.
- Параметры, которые нужно оставить неизменными, фиксируются через `family.view(...)`. Результат, `PartialParametricFamily`, — тоже `ParametricFamily`.
- Параметризация выбирается так же: `family.view(parametrization_name="meanStd")` без фиксированных параметров. Без `view` используется базовая параметризация.
- Оцениваются только свободные параметры. Компонента собирается через `family.distribution(**free)`, и `_components.fixed_parameters` у неё совпадает с `view`.
- Полностью известной компоненты, например известного фона, в первой версии нет, см. «Отложено».
- Свой тип спецификации компоненты пока не вводится. Он понадобится, если появятся настройки отдельной компоненты, а не семейства: подсказки, границы параметров, свой способ оценки для одного из одинаковых семейств.

(init-output-order)=
### Выход: порядок компонент

**Порядок компонент результата совпадает с порядком `families`.** На него опираются настройки оценщиков смеси по номеру компоненты, например `parameter_groups` у `ECM` и стратегии у `ECME`.

Одинаковые семейства различаются положением: среди них раньше в `families` стоит то, чей кластер левее, то есть с меньшим средним. Для `[normal, normal, normal]` компонента 0 — самая левая мода, компонента 2 — самая правая, в любом запуске.

### Зависимости

- Модуль зависит от `core`, `pysatl-core` и `scipy`. k-means берётся из `scipy.cluster.vq.kmeans2`, а не пишется свой.
- scikit-learn — необязательная зависимость. Он нужен только `SklearnAssigner` и ставится отдельно: `pip install pysatl-mpest[sklearn]`. Без него остальной модуль работает.
- От `estimators` и `optimizers` модуль не зависит, и `estimators` не зависит от него.
- Будущий `structure_selection` будет выдавать именно `families`, так что цепочка выглядит как «`structure_selection` → `initializers` → `estimators`».

### Граница с `estimators`

Оценка параметров при известных ответственностях — это по сути M-шаг, поэтому граница с `estimators` проводится по цели, а не по виду вычислений:

- **Инициализатор даёт дешёвую стартовую точку.** Без итераций и без численной оптимизации, только оценки в явном виде.
- **Точное совместное уточнение всей смеси — работа `estimators`.** Инициализатор оценивает компоненты по отдельным кластерам; точность смеси даст EM, запущенный из полученной смеси. Исключение — семейства, у которых носитель зависит от параметров, см. «Ограничения».

Новое в инициализаторе по сравнению с EM — только две вещи: получить ответственности, когда параметров ещё нет, и сопоставить полученные кластеры с семействами.

## Состав модуля

Планируемая раскладка, по строке на файл. `MomentsComponentEstimator`, `ComponentEstimatorChain` и `ExhaustiveMatcher` описаны в проекте, но войдут в модуль позже, см. «Первая версия».

- `initializer.py` — абстрактный `Initializer`, публичный интерфейс модуля.
- `cluster_initializer.py` — `ClusterInitializer`: инициализация по схеме «разбиение → сопоставление → оценка».
- `multi_start.py` — `MultiStartInitializer`, мультистарт поверх любого `Initializer`.
- `assigner.py`, `assigners/` — абстрактный `Assigner` и реализации `KMeansAssigner`, `SklearnAssigner`, `QuantileAssigner`, `RandomCentersAssigner`, см. [«Разбиение»](assigners/assigners.md).
- `component_estimator.py`, `component_estimators/` — абстрактный `ComponentEstimator`, реализации `MLEComponentEstimator`, `MomentsComponentEstimator` и составной `ComponentEstimatorChain`, см. [«Оценка параметров компоненты»](component_estimators/component_estimators.md).
- `_dispatch.py` — свой диспетчер формул по ключу семейства, см. {ref}`«Реестр формул» <init-formula-registry>`.
- `matcher.py`, `matchers/` — абстрактный `Matcher` и реализации `HungarianMatcher`, `ExhaustiveMatcher`, `IdentityMatcher`, см. [«Сопоставление кластеров и семейств»](matchers/matchers.md).
- `component_table.py` — `ComponentTable`, ленивая таблица компонент «семейство × кластер»: её заполняет сопоставитель, а `ClusterInitializer` берёт из неё компоненты для смеси, см. «Таблица компонент».
- `_matching.py` — чистая функция `solve_assignment(cost, groups)`: задача о назначениях по матрице стоимостей и группам одинаковых семейств, см. {ref}`«Критерий по парам» <init-hungarian>`.
- `exceptions.py` — `InitializationError` и его наследник `EstimationError`, см. «Ошибки».

Вне модуля, в `core/_components.py`, добавляются две функции над семейством:

- `family_key(family)` — ключ «имя, параметризация, отсортированные фиксированные параметры»;
- `family_fixed_parameters(family)` — фиксированные параметры семейства. Существующая `fixed_parameters(component)` становится её частным случаем.

Им место в `core`: фиксированные параметры есть только у `PartialParametricFamily`, а он не экспортируется из `pysatl_core.families`. Поэтому, как и остальные обращения к внутренностям `pysatl-core`, они живут только там (см. `core`).

(init-first-version)=
### Первая версия

В `pysatl-core` 0.1.0a0 три семейства: `Normal`, `ContinuousUniform` и `Exponential`. У всех трёх есть MLE в явном виде, а у `Normal` и `Exponential` он совпадает с методом моментов. Поэтому часть проекта сейчас нечем проверить интеграционно, без дублей:

- `MomentsComponentEstimator` отличается от `MLEComponentEstimator` только на `ContinuousUniform`, и там он хуже;
- `ComponentEstimatorChain([MLEComponentEstimator(), MomentsComponentEstimator()])` никогда не дойдёт до второго звена;
- что `ExhaustiveMatcher` даёт сверх `HungarianMatcher`, на трёх семействах не видно.

| Часть | Первая версия | Позже |
| --- | --- | --- |
| Инициализаторы и таблица | `ClusterInitializer`, `MultiStartInitializer`, `ComponentTable` | — |
| Назначатели | `KMeansAssigner`, `QuantileAssigner`, `RandomCentersAssigner`, `SklearnAssigner` | — |
| Оценщики компоненты | `MLEComponentEstimator` с формулами для трёх семейств | `MomentsComponentEstimator` и `ComponentEstimatorChain` — с первым семейством, у которого нет MLE в явном виде, но есть моменты (например, `Gamma` или `Weibull`) |
| Сопоставители | `HungarianMatcher`, `IdentityMatcher` | `ExhaustiveMatcher` — с первым примером, где `HungarianMatcher` выбирает плохую раздачу |

На диаграмме классов отложенные классы остаются, чтобы было видно, куда они встанут.

## Диаграмма классов

[Исходник диаграммы классов](diagrams/initializers.drawio "Overview")

- `Initializer` — минимальный интерфейс: `initialize(X, families, random_state=None) -> MixtureModel`. Схема «кластеры → оценка» — одна из его реализаций, а не обязательная для всех. Позже рядом могут появиться инициализаторы другого устройства, например emEM — несколько коротких запусков EM и выбор лучшего. Такой инициализатор будет зависеть от `estimators`, и зависимость останется односторонней.
- `ClusterInitializer` — единственный кластерный инициализатор с тремя заменяемыми ролями. Фасадов под отдельные способы разбиения нет: разные способы — это разные назначатели. k-means без новых зависимостей даёт `KMeansAssigner`, а любой кластеризатор scikit-learn подключается через один `SklearnAssigner`.
- `MultiStartInitializer` — тоже `Initializer` и содержит другой `Initializer`. Это обёртка: она работает с любым инициализатором, а не только с кластерным.
- Под каждой ролью — её реализации с аргументами конструктора; у реализаций без полей аргументов нет. `SklearnAssigner` принимает кластеризатор типа `ClusterMixin` — базового класса кластеризаторов scikit-learn.
- `ComponentEstimatorChain` сам является `ComponentEstimator` и содержит список других оценщиков компоненты `estimators`.
- `ComponentTable` создаёт `ClusterInitializer` на каждый вызов `initialize` и передаёт её в `Matcher.match`. Таблица живёт один вызов `initialize`: новое разбиение — новая таблица.
- Оценщик компоненты таблица получает в конструкторе от `ClusterInitializer` и хранит в приватном поле `estimator` (агрегация на рисунке). Вызывает его только она, поэтому ни сопоставитель, ни шаг оценки к `ComponentEstimator` напрямую не обращаются.

Роли `ClusterInitializer` и их значения по умолчанию:

| Роль | По умолчанию |
| --- | --- |
| `Assigner` | Нет, передаётся явно: способ разбиения сильнее всего влияет на результат, и пользователь выбирает его сам |
| `ComponentEstimator` | `MLEComponentEstimator()`. Когда появится `ComponentEstimatorChain` — `ComponentEstimatorChain([MLEComponentEstimator(), MomentsComponentEstimator()])` |
| `Matcher` | `HungarianMatcher` |

На рисунке сознательно не проведены:

- зависимость `Matcher` от `ComponentTable`, видная из сигнатуры `match`;
- использование `core._components.family_key` в `ComponentTable` и `_dispatch`;
- зависимость `ComponentEstimator` от `ParametricFamilyDistribution`, видная из сигнатуры `estimate`;
- вызов `scipy.cluster.vq.kmeans2` из `KMeansAssigner`;
- вызов `scipy.optimize.linear_sum_assignment` из `HungarianMatcher`: он показан на схеме сопоставления.

## Устройство

(init-walk)=
### Ход `initialize`

[Исходник схемы вызовов](diagrams/initializers.drawio "Sequence: initialize")

`ClusterInitializer.initialize(X, families, random_state)` выполняет восемь действий:

1. **Проверка входа** — всё, что можно проверить до разбиения, см. ниже.
2. **Разбиение.** Из `random_state` создаётся генератор `rng = np.random.default_rng(random_state)`, и `Assigner.assign(X, k, rng)` возвращает матрицу `H` размера `(n, k)`, где `k = len(families)`. Столбец `H` — один кластер. `ClusterInitializer` проверяет структуру `H` и размер кластеров (см. «Вырожденные кластеры») и переставляет столбцы по возрастанию среднего значения кластера.
3. **Таблица.** Создаётся пустая `ComponentTable(X, H, families, estimator)`.
4. **Сопоставление.** `Matcher.match(table)` возвращает перестановку `assignment`: элемент `families[j]` получает столбец `H[:, assignment[j]]`. `ClusterInitializer` проверяет, что это действительно перестановка.
5. **Оценка.** Для каждого `j` компонента берётся из таблицы: `table.component(j, assignment[j])`.
6. **Веса.** Вес компоненты — средняя ответственность её кластера, см. «Веса».
7. **Сборка.** Создаётся `MixtureModel(components, weights)`.
8. **Проверка результата.** `loglikelihood(X)` смеси должен быть конечен.

**Проверка входа.** Чтобы кластеризация, самая дорогая часть, не запускалась зря, до разбиения проверяется:

- `families` не пуст;
- `X` одномерный, и все его значения конечны (без `NaN` и $\pm\infty$);
- `n >= k · min_cluster_size`, иначе ни одно разбиение не пройдёт порог размера;
- различных значений в выборке не меньше `k`;
- `estimator.supports(family)` истинно для каждого семейства.

Иначе `ValueError`, а для неподдерживаемых семейств — `NotImplementedError` со списком всех таких семейств, а не только первого.

**Сортировка столбцов.** Номера кластеров у назначателя произвольны: метки `KMeans` от запуска к запуску разные. После сортировки столбец 0 — самый левый кластер, и на этом держится порядок одинаковых семейств из «Выход: порядок компонент».

**Проверка перестановки.** `assignment` должен быть перестановкой чисел `0…k−1`: длина `k`, числа целые, различные, каждое в диапазоне. Иначе `ValueError` с полученным значением, например «Matcher вернул не перестановку длины 3: [0, 0, 1]». Без проверки ошибка всплыла бы далеко от причины: `IndexError` в таблице или `ValueError` о сумме весов из `MixtureModel`.

**Повторной оценки на действии 5 нет**, если сопоставитель эту пару уже запрашивал. Иначе таблица оценивает её сейчас. Так бывает с `IdentityMatcher` и с `HungarianMatcher`, когда все семейства одинаковые и он к таблице не обращается.

**Проверка результата.** Если `loglikelihood(X)` смеси не конечен, бросается `InitializationError` с примерами точек, которые не покрывает ни одна компонента. Так бывает, только когда раздачу выбрали, не глядя в таблицу: с `IdentityMatcher` и с `HungarianMatcher` при одинаковых семействах. Например, у `[expon, expon]` кластер `{−1, 5}` оценивается (`lambda_ = 0.5`), но точку −1 не покрывает ни одна компонента.

**Состояние.** Изменяемого состояния вроде `PipelineState` нет: между стадиями передаются только `H`, таблица и `assignment`. Таблица меняется только как кэш: она запоминает уже посчитанные пары, и от порядка запросов её ответы не зависят. Порядок стадий фиксирован, поэтому `ClusterInitializer` принимает роли по имени, а не список шагов, как `Pipeline`.

### Роли

Действия 2, 4 и 5 выполняют заменяемые роли. Каждая разобрана на своей подстранице:

| Роль | Что делает | Подробно |
| --- | --- | --- |
| `Assigner` | Разбивает выборку на `k` кластеров и возвращает матрицу `H` | [«Разбиение»](assigners/assigners.md) |
| `Matcher` | Решает, какой кластер достаётся какому семейству | [«Сопоставление кластеров и семейств»](matchers/matchers.md) |
| `ComponentEstimator` | Оценивает параметры компоненты по точкам кластера | [«Оценка параметров компоненты»](component_estimators/component_estimators.md) |

(init-component-table)=
### Таблица компонент

Сопоставители работают с парами «семейство — кластер» через `ComponentTable`:

- `table.component(j, c)` возвращает компоненту семейства `families[j]`, оценённую на столбце $c$ матрицы `H` тем же `ComponentEstimator`, что и на шаге оценки;
- `table.loglikelihood(j, c)` — её логарифм правдоподобия $\ell_{jc}$ на этом кластере;
- `table.groups()` — группы одинаковых семейств, см. «Одинаковые семейства» ниже.

Свойства таблицы:

- **Ленивая.** Пару она оценивает при первом запросе и запоминает. Одинаковые семейства делят записи, поэтому при $d$ различных семействах оценок не больше $d \cdot k$, а не $k^2$.
- **Невозможная пара запоминается.** Если оценщик компоненты пару оценить не смог (`EstimationError`), таблица сохраняет ошибку с указанием пары: новый `EstimationError` вида «семейство 2 (`Exponential`), кластер 1: <причина от оценщика>», исходная ошибка — в `__cause__`. Для такой пары `loglikelihood` равен $-\infty$, а `component` снова бросает сохранённую ошибку, не вызывая оценщик компоненты повторно.
- **Значения нормализованы.** `loglikelihood` — конечное число или $-\infty$. `NaN` и $+\infty$, откуда бы они ни пришли (из `lpdf` компоненты или из формулы), таблица сама записывает как $-\infty$, то есть как невозможную пару. Сопоставителям других значений проверять не нужно.

Как таблица оценивает одну пару, показано на схеме {ref}`«Ход estimate» <init-estimate-walk>`. `IdentityMatcher` к таблице не обращается и ничего не оценивает; остальные сопоставители различаются тем, какие пары они запрашивают, см. [«Сопоставление кластеров и семейств»](matchers/matchers.md).

(init-identical-families)=
#### Одинаковые семейства

- Ключ семейства — тройка «имя семейства, параметризация, фиксированные параметры», `_components.family_key(family)`. Два `Normal` с фиксированными `mu=0` и `mu=5` — разные семейства, и сопоставление для них нужно.
- Группы одинаковых семейств считает только `ComponentTable` и отдаёт методом `groups()` — списком групп индексов в `families`, в порядке первого вхождения.
- Сопоставители и шаг оценки свои ключи не считают. Если бы таблица и группировка считали одинаковость по-разному, `normal.view(mu=0)` мог бы получить из общей записи компоненту, оценённую как свободный `normal`.

(init-randomness)=
### Случайность

Случайность передаётся аргументом вызова, а не хранится в объектах. `initialize(X, families, random_state=None)` принимает `random_state` — `int`, `np.random.Generator` или `None`, как `MixtureModel.generate`. `ClusterInitializer` создаёт из него генератор `rng` и передаёт его в `assign(X, n_components, rng)`. Ни у одной роли нет поля со своим генератором, поэтому:

| `random_state` | Поведение |
| --- | --- |
| Целое число | Одинаковые аргументы дают одинаковую смесь, независимо от того, сколько раз объект вызывали раньше |
| `np.random.Generator` | Используется на месте, без копии, и сдвигается, как в `generate`: `np.random.default_rng(g)` возвращает сам `g`, а `g.spawn` сдвигает его счётчик потомков. Два вызова с одним объектом генератора дают разные смеси. Ради этого генератор и передают: серия вызовов из одного потока случайности |
| `None` | Каждый вызов берёт свежую энтропию и не воспроизводится, как в numpy |

- Воспроизводимость с целым сидом нужна `structure_selection`: старт для одного числа компонент не зависит от того, перебирались ли до него другие. Для этого каждому числу компонент передаётся свой сид или свой потомок через `spawn`, а не один общий генератор.
- Детерминированный назначатель, например `QuantileAssigner`, аргумент `rng` не использует.

Кластеризаторы scikit-learn генератор не принимают, поэтому `SklearnAssigner` переводит `rng` в целый сид, см. {ref}`SklearnAssigner <init-sklearn-assigner>`.

### Веса

Вес компоненты $j$ — средняя ответственность её кластера:

$$
\pi_j = \frac{1}{n} \sum_{i=1}^{n} \gamma_{i\sigma(j)}.
$$

Правило одно и не зависит от ролей, поэтому отдельной роли для весов нет.

(init-degenerate)=
### Вырожденные кластеры

Параметры не удаётся оценить не только по пустому кластеру, но и по любому вырожденному:

- **пустой кластер** — у кластеризатора центр остался без точек;
- **слишком мало точек** — например, кластер из одной точки;
- **нет разброса** — кластер целиком из одинаковых или почти одинаковых значений, частый случай при повторах в выборке.

Проверки распределены между участниками так:

| Что проверяется | Кто и когда | Ошибка |
| --- | --- | --- |
| Форма `H` — `(n, k)`, в каждой строке ровно одна единица среди нулей | `ClusterInitializer` после разбиения | `ValueError`: ошибка в назначателе |
| Пустой кластер | `KMeansAssigner` при разбиении, для остальных назначателей — `ClusterInitializer` после него | `InitializationError` |
| Размер каждого кластера не меньше `min_cluster_size` | `ClusterInitializer` после разбиения, до сопоставления | `InitializationError` |
| Различных значений в кластере не меньше, чем свободных параметров | Оценщик компоненты при оценке пары | `EstimationError` |
| Параметры допустимы и конечны (`sigma = 0`, `lambda_ < 0`, `NaN`) | Оценщик компоненты при оценке пары | `EstimationError` |
| Масштаб больше порога, у `Normal` ещё дисперсия больше `NUMERICAL_TOLERANCE` | Оценщик компоненты при оценке пары | `EstimationError` |

#### Структура разбиения

- **Назначатель и `ClusterInitializer` проверяют только структуру.** `KMeans` из scikit-learn сам переносит центры опустевших кластеров; `kmeans2` и остальные кластеризаторы этого не делают, и мы их не чиним.
- **Неверная структура `H` — `ValueError`:** это ошибка в назначателе, и другое разбиение её не исправит. Пустой столбец — `InitializationError`.
- **У `SklearnAssigner` не бывает** «шумовых» меток (`-1` у `DBSCAN`) и неверного числа кластеров: он принимает только кластеризаторы с `n_clusters`.
- **Ошибки входа ловятся до разбиения.** Если `n < k` или различных значений в выборке меньше `k`, сразу `ValueError`: это ошибка входа, а не неудачное разбиение.

#### Достаточность данных

- **Проверяет оценщик компоненты.** Сколько данных нужно, знает только способ оценки: назначатель не видит ни семейств, ни формул.
- **Нижняя граница вычислимости** — различных значений в кластере не меньше, чем свободных параметров: иначе условий меньше, чем неизвестных. Например, `MomentsComponentEstimator` для `Normal` требует хотя бы двух различных значений, иначе `sigma = 0`.
- **Ошибка понятная.** Если по формулам получаются недопустимые параметры (`sigma = 0`, `lambda_ < 0`) или данных не хватает, оценщик компоненты бросает `EstimationError` с причиной, а не `ValueError` из глубины `pysatl-core`. На шаге сопоставления такая пара просто становится невозможной, см. {ref}`«Невозможные пары» <init-impossible-pairs>`.
- **Цепочка не передаёт кластер дальше.** В `ComponentEstimatorChain` `EstimationError` не передаёт кластер следующему способу: иначе одинаковые семейства могли бы оказаться оценены разными способами, а `supports(family)` отвечает только на вопрос, есть ли формулы.

#### Численная вырожденность

Ровно нулевой `sigma` в арифметике с плавающей точкой обычно не получается: у кластера из семи значений `0.1` дисперсия около `1e-34`, `sigma` около `1e-17`, и ограничение `sigma > 0` у `pysatl-core` это пропускает. Поэтому вырожденность проверяет сам оценщик компоненты. Масштаб оценённой компоненты должен быть больше порога, заданного относительно разброса всей выборки:

$$
s_j > \varepsilon \cdot \operatorname{std}(X), \qquad \varepsilon = 10^{-6},
$$

где $s_j$ — `sigma` у `Normal`, $1/\lambda$ у `Exponential`, ширина $b - a$ у `ContinuousUniform`.

- Порог относительный, поэтому не зависит от единиц измерения.
- Для `Normal` дополнительно нужна дисперсия больше `NUMERICAL_TOLERANCE` M-шага (`1e-9`): при меньшей M-шаг `sigma` не обновляет, и старт застрял бы в EM навсегда.
- Иначе — `EstimationError`, и пара становится невозможной.

#### Порог размера кластера

Порог включён по умолчанию, потому что численный порог узкие кластеры не ловит:

- правдоподобие смеси не ограничено сверху: при `sigma → 0` или ширине `ContinuousUniform → 0` оно растёт, поэтому и критерий `HungarianMatcher`, и критерий мультистарта предпочитают узкие кластеры из нескольких выбросов;
- у двух выбросов `20.0` и `20.001` `sigma = 0.0005` численно нормальна.

Правило:

- `ClusterInitializer(min_cluster_size=None)` по умолчанию требует в каждом кластере не меньше $2 p$ точек, где $p$ — наибольшее число свободных параметров среди `families`: 4 точки для `Normal` и `ContinuousUniform`, 2 для `Exponential`;
- целое значение задаёт порог явно, `min_cluster_size=1` отключает проверку;
- кластер меньше порога делает запуск неудачным (`InitializationError`), с `MultiStartInitializer` такие разбиения просто отбрасываются;
- порог проверяется на действии 2, до сопоставления, и не зависит от того, какое семейство получит кластер.

#### Чего нет

- **Никаких молчаливых подстановок** вроде «взять оценку по всей выборке»: такая смесь выглядит нормально, но построена не так, как думает пользователь.
- **Повторные попытки** — дело `MultiStartInitializer`, а не отдельной логики внутри.

(init-errors)=
### Ошибки

Ошибки инициализатора делятся на два вида и ловятся по-разному:

- **Неудачное разбиение** — `InitializationError` и его наследник `EstimationError`. В таблице ниже это все строки с этими типами. Другое разбиение может пройти, поэтому такие ошибки ловят таблица (только `EstimationError`, на сопоставлении) и `MultiStartInitializer`.
- **Всё остальное** (`ValueError`, `NotImplementedError`, `ImportError`, `TypeError`) пробрасывается без перехвата: ошибки входа и конфигурации, неподдерживаемое семейство, ошибки в коде. Повтор с другим разбиением их не исправит, а перехват спрятал бы настоящую проблему.

| Ситуация | Ошибка | Где возникает |
| --- | --- | --- |
| `families` пуст, `X` не одномерный или с неконечными значениями, `n < k · min_cluster_size`, различных значений меньше `k` | `ValueError` | Проверка входа |
| Семейство не поддерживается оценщиком компоненты | `NotImplementedError` со списком всех таких семейств | Проверка входа |
| scikit-learn не установлен | `ImportError` | Конструктор `SklearnAssigner` |
| Кластеризатор без `n_clusters` | `ValueError` | Конструктор `SklearnAssigner` |
| Неверная структура `H` | `ValueError` | `ClusterInitializer` после разбиения |
| Пустой кластер | `InitializationError` | `KMeansAssigner` или `ClusterInitializer` |
| Кластер меньше `min_cluster_size` | `InitializationError` | `ClusterInitializer` после разбиения |
| Пару «семейство — кластер» нельзя оценить | `EstimationError` | Оценщик компоненты; на сопоставлении таблица делает пару невозможной |
| Нет раздачи, где каждое семейство получает подходящий кластер | `InitializationError` | `solve_assignment`, `ExhaustiveMatcher` |
| Пару, выбранную без таблицы (`IdentityMatcher`), нельзя оценить | `EstimationError` | Действие 5 |
| Сопоставитель вернул не перестановку | `ValueError` | `ClusterInitializer` после `match` |
| Вариантов раздачи больше `max_candidates` | `ValueError` | `ExhaustiveMatcher` |
| Смесь не покрывает часть выборки | `InitializationError` с примерами точек | Проверка результата |
| Формула вернула фиксированный параметр | `ValueError` или `TypeError` из `pysatl-core` | Сборка компоненты; это ошибка в формуле, а не в данных |
| Все запуски мультистарта неудачны | `InitializationError`, причина последнего запуска в `__cause__` | `MultiStartInitializer` |

### Мультистарт

[Исходник схемы мультистарта](diagrams/initializers.drawio "Sequence: multistart")

`MultiStartInitializer(initializer, n_init)` вызывает `initializer.initialize(X, families, random_state=child)` `n_init` раз, каждый раз со своим генератором `child`, считает `loglikelihood(X)` каждой смеси и возвращает смесь с наибольшим значением.

- **Разные результаты при повторах.** Обёртка создаёт генератор из своего `random_state` и делит его на `n_init` независимых генераторов через `rng.spawn(n_init)`. Каждый запуск получает свой, поэтому запуски различаются, воспроизводятся при одном целом `random_state` и не зависят друг от друга: их можно выполнять параллельно.
- **Ошибки отдельных запусков.** Если запуск упал с `InitializationError`, например на вырожденном кластере, обёртка пропускает его. Другие ошибки она не ловит, см. «Ошибки». Ошибку она бросает, только если упали все запуски, и прикладывает причину последнего. Так мультистарт заодно закрывает редкие вырожденные разбиения.
- **С детерминированным инициализатором** (например, с `QuantileAssigner`) мультистарт бесполезен: все запуски одинаковы.
- **Критерий — правдоподобие стартовой смеси,** а не результат EM. Это дёшево, но лучший старт не обязательно приводит к лучшему итогу. Критерий не ограничен сверху и тянется к узким кластерам; от них защищают численный порог оценщика компоненты и `min_cluster_size`, см. «Вырожденные кластеры». Вариант «прогнать каждого кандидата несколькими итерациями EM» (emEM) — отдельный будущий инициализатор.

## Как расширить

- **Кластеризатор scikit-learn.** Поставить `pysatl-mpest[sklearn]` и передать кластеризатор в `SklearnAssigner`.
- **Назначатель.** Унаследовать `Assigner` и реализовать `assign`: вернуть матрицу `(n, n_components)`, в каждой строке которой ровно одна единица, остальные нули. Случайность брать только из аргумента `rng`, не хранить генератор в объекте.
- **Формулы для нового семейства `pysatl-core`** (доработка библиотеки, а не пользовательское расширение), см. {ref}`«Контракт формулы» <init-formula-contract>`. Добавить функцию `formula(X, h, fixed) -> dict` и зарегистрировать её вызовом в приватном реестре нужного способа, например `MLEComponentEstimator` или `MomentsComponentEstimator`, для пары «семейство, параметризация». Она должна учитывать `fixed` и возвращать только свободные параметры.
- **Новый способ оценки.** Унаследовать `ComponentEstimator`, реализовать `supports` и `estimate` и поставить способ в нужное место `ComponentEstimatorChain`. Если по данным кластера параметры не получаются, бросать `EstimationError`. Способ в явном виде можно добавлять в цепочку по умолчанию, численный — нет.
- **Сопоставитель.** Унаследовать `Matcher` и реализовать `match`: вернуть перестановку длины `k`, иначе `ClusterInitializer` бросит `ValueError`. Компоненты и $\ell_{jc}$ брать из переданной `ComponentTable`, а не оценивать заново.
- **Инициализатор другого устройства.** Унаследовать `Initializer` напрямую; мультистарт с ним работает без изменений.

## Ограничения и решения

(init-limitations)=
### Ограничения

- **Носитель, зависящий от параметров, оценщик смеси не расширяет.** Оценка `ContinuousUniform` по кластеру — минимум и максимум его точек, поэтому носитель стартовой компоненты равен диапазону кластера.
  - В EM точки вне носителя получают нулевую ответственность, и Q-функция растёт при сужении отрезка: границы могут только сужаться.
  - `ECME` с максимизацией правдоподобия всей смеси расширяет их лишь частично и застревает в локальном максимуме, когда соседняя компонента уже покрыла недостающие точки.
  - Например, на 600 точках `U(0, 10)` и 400 точках `N(5, 0.5)` старт `U(0.05, 5.82)` после 100 итераций EM остаётся `U(0.05, 5.82)`, а у `ECME` становится `U(0.05, 5.94)`. Нормальная компонента расплывается до `N(5.97, 1.84)`, логарифм правдоподобия около −2166 против −2043 у истинной смеси.
  - Для таких смесей нужен мультистарт или старт, заданный вручную.
- **Назначатель не знает семейств.** Для смесей с разными носителями (например, `Normal` и `Exponential`) кластеры могут не подойти ни одному семейству. Сопоставление выбирает лучшую из возможных пар, но не исправляет разбиение.
- **Назначатель не учитывает фиксированные параметры.** Обычно это исправляет сопоставление: у `[normal.view(mu=0), normal]` на модах около 0 и около 10 семейство с `mu=0` получит кластер около 0, потому что на другом кластере его правдоподобие хуже. Но если ни один кластер не лежит около зафиксированного значения, например широкая компонента вокруг 0 и узкая около 3 дают кластеры около −3 и 3, стартовая `sigma` у `normal.view(mu=0)` будет смещена. Исправляют это EM, запущенный из полученной смеси (фиксированный `mu` там тоже держится), или мультистарт с другим разбиением.
- **Формулы оценки регистрируются по параметризации.** У `Normal` их четыре (`meanStd`, `meanVar`, `meanPrec`, `exponential`), а преобразования из базовой параметризации в другую в `pysatl-core` нет, поэтому формулы `meanStd` для `meanVar` не переиспользовать.
  - `normal.view(parametrization_name="meanVar")` с цепочкой по умолчанию даст `NotImplementedError` на проверке входа, пока для `meanVar` не зарегистрированы свои формулы.
  - Когда формулы появятся, `normal` и `normal.view(parametrization_name="meanVar")` будут разными семействами, хотя это одна модель: ключ семейства включает параметризацию, а перевода между параметризациями в `pysatl-core` нет. Смесь от этого не портится: у таких семейств одинаковые $\ell_{jc}$, и любая раздача между ними даёт ту же смесь. Цена — лишние оценки в таблице и не нормализованный порядок этих компонент.
- **Сопоставление оптимально только относительно оценок выбранного способа:** оба критерия считаются в точке оценки `ComponentEstimator`, а не в максимуме правдоподобия.
- **Число вариантов у `ExhaustiveMatcher` растёт комбинаторно:** при многих разных семействах он неприменим.
- **Семейство без формул в явном виде пока инициализировать нельзя:** численного способа оценки нет, он отложен.
- **Только жёсткое разбиение и только одномерные выборки.**

### Принятые решения

| Вопрос | Решение |
| --- | --- |
| Имя метода | `initialize(X, families, random_state=None)` |
| Случайность | Аргумент вызова: `random_state` у `initialize`, `rng` у `assign`. У ролей нет своего генератора, мультистарт делит генератор через `spawn` |
| Тип элемента `families` | `ParametricFamily`; свой тип — когда появятся настройки отдельной компоненты |
| Порядок одинаковых семейств | По возрастанию среднего их кластеров: `ClusterInitializer` сортирует столбцы `H`, сопоставители раздают кластеры внутри группы в порядке столбцов |
| Разбиение | Роль `Assigner`, только жёсткое: `H` из единиц и нулей, по одной единице в строке, это проверяет `ClusterInitializer`. Назначатель передаётся явно, по умолчанию его нет |
| k-means | `KMeansAssigner` на `scipy.cluster.vq.kmeans2`, своего k-means нет |
| Кластеризаторы scikit-learn | Только с параметром `n_clusters`, через `SklearnAssigner`; scikit-learn — необязательная зависимость (`pysatl-mpest[sklearn]`). Число кластеров берётся из `families` и подставляется в копию кластеризатора, `n_clusters` пользователя игнорируется; кластеризаторы без `n_clusters` отвергаются |
| Случайный старт | `RandomCentersAssigner` по случайным центрам, не по случайным меткам |
| Вырожденные кластеры | Назначатель и `ClusterInitializer` проверяют структуру разбиения, оценщик компоненты — достаточность данных и численную вырожденность (масштаб больше $10^{-6} \cdot \operatorname{std}(X)$, у `Normal` ещё дисперсия больше `NUMERICAL_TOLERANCE` M-шага). `min_cluster_size` по умолчанию $2p$ точек, $p$ — наибольшее число свободных параметров. Никаких подстановок, повторы через мультистарт |
| Мультистарт | Обёртка `MultiStartInitializer` поверх любого `Initializer` |
| Ошибки | `InitializationError` для неудачного разбиения и наследник `EstimationError` для пары, которую нельзя оценить. Невозможная пара не обрывает сопоставление, а исключается из раздач; ловятся только эти два типа |
| Таблица компонент | Ленивый кэш `ComponentTable`, общий для сопоставления и шага оценки: каждая пара «семейство — кластер» оценивается не больше одного раза при любом сопоставителе |
| Способы оценки | В первой версии только `MLEComponentEstimator`, он же по умолчанию. `MomentsComponentEstimator`, `ComponentEstimatorChain` и `ExhaustiveMatcher` — позже, с первым случаем, где они нужны |
| Контракт формулы | `formula(X, h, fixed) -> dict` свободных параметров; фиксированные параметры входят аргументом |
| Диспетчеризация по семейству | Свой диспетчер в `initializers`, ключ берётся у семейства, а не у компоненты. Реестр формул приватный, на уровне модуля, формулы регистрируются вызовом, как у `FamilyDispatch` в `estimators`. Публичной регистрации формул нет, расширение способа оценки — через `ComponentEstimator`. Общий диспетчер и общие формулы с M-шагом — отдельной задачей |

(init-deferred)=
### Отложено

- **Полностью известная компонента** — готовое `ParametricFamilyDistribution` в `families`, например известный фон.
  - Через `view` её не выразить: `pysatl-core` запрещает фиксировать все параметры.
  - Оценщики смеси её не сохранят: `EM` оптимизирует все свободные параметры, а у готового распределения свободны все; `ECM` не даёт оставить компоненту без групп. Поэтому сначала нужна заморозка целой компоненты в `estimators`.
  - Ей нужен свой ключ, отличный от ключа семейства.
  - Вес по одному жёсткому кластеру занижает вес фона, перекрытого другими компонентами.
- **Назначатель, учитывающий семейства,** например k-means с неподвижными центрами для фиксированных параметров положения, в паре с `IdentityMatcher`. Нужно передать `families` в `assign`; помогает только параметрам положения.
- **Численный способ оценки через `Optimizer`.** Оптимизатору нужна начальная точка, а у семейства без формул её взять неоткуда. Решается вместе с первым таким семейством.
- **Мягкое разбиение.** При нём почти каждая точка имеет вес в каждом кластере, поэтому нужно заново определить: какой вес считать принадлежностью к кластеру, размер кластера для проверок и `min_cluster_size`, носитель и невозможные пары, границы `ContinuousUniform`. Сигнатура `estimate(X, h, family)` останется, но контракт `h` придётся расширить с маски на дробные веса.
- **Способ оценки по L-моментам.** Устойчивее к выбросам, подходит для GEV, Gumbel, Pareto, но строится по порядковым статистикам и требует решить, как работать с мягким разбиением.
