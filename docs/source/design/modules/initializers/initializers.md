# Модуль `initializers`
**Назначение:** описать проект модуля, который подбирает начальную смесь `MixtureModel` по выборке и заданным семействам компонент, и зафиксировать принятые решения (Запланировано).

Модуля в коде пока нет: сейчас начальную `MixtureModel` с параметрами задаёт пользователь, см. [«Модуль `core`»](../core/core.md). Ниже описан проект. Имена классов и сигнатуры предварительные, конкретные реализации ролей пока не детализированы.

## Задача

Инициализатор получает выборку `X` и список `families`, по элементу на компоненту, и возвращает `MixtureModel` с полностью заданными параметрами и весами. Результат передаётся в `fit` оценщиков смеси из `estimators`.

Слово «оценщик» в этом документе всегда уточняется. **Оценщик смеси** — `EM`, `ECM`, `ECME` из `estimators`: оценивают всю смесь. **Оценщик компоненты** — `ComponentEstimator` и его реализации в `initializers`: оценивают параметры одной компоненты по кластеру.

```python
normal = ParametricFamilyRegister.get(FamilyName.NORMAL)
expon = ParametricFamilyRegister.get(FamilyName.EXPONENTIAL)

initializer = ClusterInitializer(KMeansAssigner())
start = MultiStartInitializer(initializer, n_init=10).initialize(X, [normal, normal, expon], random_state=42)
result = EM(...).fit(X, start)
```

Элемент `families` — `ParametricFamily | ParametricFamilyDistribution` из `pysatl-core`:

- **Семейство** (`ParametricFamily`). Параметры, которые нужно оставить неизменными, фиксируются через `family.view(...)`: результат, `PartialParametricFamily`, — тоже `ParametricFamily`. Параметризация выбирается так же: `family.view(parametrization_name="meanStd")` без фиксированных параметров. Без `view` используется базовая параметризация. Оцениваются только свободные параметры; компонента собирается через `family.distribution(**free)`, и `_components.fixed_parameters` у неё совпадает с `view`.
- **Готовое распределение** (`ParametricFamilyDistribution`) — полностью известная компонента, например известный фон. Через `view` её не выразить: `pysatl-core` запрещает фиксировать все параметры. У такой компоненты оценивается только вес.

Свой тип спецификации компоненты пока не вводится. Он понадобится, если появятся настройки отдельной компоненты, а не семейства: подсказки, границы параметров, свой способ оценки для одного из одинаковых семейств.

**Порядок компонент результата совпадает с порядком `families`.** На него опираются настройки оценщиков смеси по номеру компоненты, например `parameter_groups` у `ECM` и стратегии у `ECME`. Одинаковые семейства различаются положением: среди них раньше в `families` стоит то, чей кластер левее, то есть с меньшим средним. Для `[normal, normal, normal]` компонента 0 — самая левая мода, компонента 2 — самая правая, в любом запуске.

Модуль зависит от `core`, `pysatl-core` и `scipy`: k-means берётся из `scipy.cluster.vq.kmeans2`, а не пишется свой (см. «Шаг 1»). scikit-learn — необязательная зависимость: он нужен только `SklearnAssigner` и ставится отдельно, `pip install pysatl-mpest[sklearn]`. Без него остальной модуль работает. От `estimators` и `optimizers` модуль не зависит, и `estimators` не зависит от него. Будущий `structure_selection` будет выдавать именно `families`, так что цепочка выглядит как «`structure_selection` → `initializers` → `estimators`».

### Граница с `estimators`

Оценка параметров при известных ответственностях — это по сути M-шаг, поэтому граница с `estimators` проводится по цели, а не по виду вычислений:

- **Инициализатор даёт дешёвую стартовую точку.** Без итераций и без численной оптимизации, только оценки в явном виде.
- **Точное совместное уточнение всей смеси — работа `estimators`.** Инициализатор оценивает компоненты по отдельным кластерам; точность смеси даст EM, запущенный из полученной смеси.

Новое в инициализаторе по сравнению с EM — только две вещи: получить ответственности, когда параметров ещё нет, и сопоставить полученные кластеры с семействами.

## Состав модуля

Планируемая раскладка, по строке на файл. `MomentsEstimator`, `EstimatorChain` и `ExhaustiveMatcher` описаны в проекте, но войдут в модуль позже, см. «Первая версия».

- `initializer.py` — абстрактный `Initializer`, публичный интерфейс модуля.
- `cluster_initializer.py` — `ClusterInitializer`: инициализация по схеме «разбиение → сопоставление → оценка».
- `multi_start.py` — `MultiStartInitializer`, мультистарт поверх любого `Initializer`.
- `assigner.py`, `assigners/` — абстрактный `Assigner` (шаг 1) и реализации `KMeansAssigner`, `SklearnAssigner`, `QuantileAssigner`, `RandomAssigner`.
- `component_estimator.py`, `component_estimators/` — абстрактный `ComponentEstimator` (шаг 2), реализации `MLEEstimator`, `MomentsEstimator` и составной `EstimatorChain`.
- `_dispatch.py` — свой диспетчер формул: выбирает формулу по паре «имя семейства, параметризация» самого семейства. Это не копия `FamilyDispatch` из `estimators.iterative._strategies`: тот берёт ключ у готовой компоненты, а на шаге оценки компоненты ещё нет. Импортировать его нельзя, иначе `initializers` зависел бы от `estimators`.
- `matcher.py`, `matchers/` — абстрактный `Matcher` и реализации `HungarianMatcher`, `ExhaustiveMatcher`, `IdentityMatcher`.
- `component_table.py` — `ComponentTable`, ленивая таблица компонент «семейство × кластер»: её заполняет сопоставитель, а `ClusterInitializer` берёт из неё компоненты для смеси.
- `_matching.py` — общие части сопоставителей: группировка одинаковых семейств и порядок кластеров внутри группы.
- `exceptions.py` — `InitializationError` и его наследник `EstimationError`, см. «Ошибки».

### Первая версия

В `pysatl-core` 0.1.0a0 три семейства: `Normal`, `ContinuousUniform` и `Exponential`. У всех трёх есть MLE в явном виде, а у `Normal` и `Exponential` он совпадает с методом моментов. Поэтому часть проекта сейчас нечем проверить интеграционно, без дублей:

- `MomentsEstimator` отличается от `MLEEstimator` только на `ContinuousUniform`, и там он хуже;
- `EstimatorChain([MLEEstimator(), MomentsEstimator()])` никогда не дойдёт до второго звена;
- что `ExhaustiveMatcher` даёт сверх `HungarianMatcher`, на трёх семействах не видно.

Первая версия: `ClusterInitializer`, `MultiStartInitializer`, `ComponentTable`, назначатели `KMeansAssigner`, `QuantileAssigner`, `RandomAssigner`, `SklearnAssigner`, `MLEEstimator` с формулами для трёх семейств, `HungarianMatcher` и `IdentityMatcher`. Позже: `MomentsEstimator` и `EstimatorChain` — с первым семейством, у которого нет MLE в явном виде, но есть моменты (например, `Gamma` или `Weibull`); `ExhaustiveMatcher` — с первым примером, где `HungarianMatcher` выбирает плохую раздачу. На диаграмме классов они остаются, чтобы было видно, куда встанут.

## Диаграмма классов

[Исходник диаграммы классов](diagrams/initializers.drawio "Overview")

- `Initializer` — минимальный интерфейс: `initialize(X, families, random_state=None) -> MixtureModel`. Схема «кластеры → оценка» — одна из его реализаций, а не обязательная для всех. Позже рядом могут появиться инициализаторы другого устройства, например emEM — несколько коротких запусков EM и выбор лучшего. Такой инициализатор будет зависеть от `estimators`, и зависимость останется односторонней.
- `ClusterInitializer` — единственный кластерный инициализатор с тремя заменяемыми ролями: `Assigner`, `ComponentEstimator` и `Matcher`. Фасадов под отдельные способы разбиения нет: разные способы — это разные назначатели: k-means без новых зависимостей даёт `KMeansAssigner`, а любой кластеризатор scikit-learn подключается через один `SklearnAssigner`. По умолчанию оценщик компоненты — `MLEEstimator()`, сопоставитель — `HungarianMatcher`. Когда появится `EstimatorChain`, оценщиком компоненты по умолчанию станет `EstimatorChain([MLEEstimator(), MomentsEstimator()])`. Назначатель по умолчанию не задан и передаётся явно: способ разбиения сильнее всего влияет на результат, и пользователь выбирает его сам.
- `MultiStartInitializer` — тоже `Initializer` и содержит другой `Initializer`. Это обёртка: она работает с любым инициализатором, а не только с кластерным.
- Под каждой ролью — её реализации с аргументами конструктора; у реализаций без полей аргументов нет. `SklearnAssigner` принимает кластеризатор типа `ClusterMixin` — базового класса кластеризаторов scikit-learn.
- `EstimatorChain` сам является `ComponentEstimator` и содержит список других оценщиков компоненты `estimators`.
- `ComponentTable` создаёт `ClusterInitializer` на каждый вызов `initialize` и передаёт её в `Matcher.match`. Оценщик компоненты таблица получает в конструкторе от `ClusterInitializer` и хранит в приватном поле `estimator` (агрегация на рисунке); вызывает его только она, поэтому ни сопоставитель, ни шаг оценки к `ComponentEstimator` напрямую не обращаются. Таблица живёт один вызов `initialize`: новое разбиение — новая таблица.
- Не проведены: зависимость `Matcher` от `ComponentTable`, видная из сигнатуры `match`; зависимость `ComponentEstimator` от `ParametricFamilyDistribution`, видная из сигнатуры `estimate`; вызов `scipy.cluster.vq.kmeans2` из `KMeansAssigner`; вызов `scipy.optimize.linear_sum_assignment` из `HungarianMatcher` (он показан на схеме сопоставления).

## Устройство

### Ход `initialize`

[Исходник схемы вызовов](diagrams/initializers.drawio "Sequence: initialize")

`ClusterInitializer.initialize(X, families, random_state)` выполняет восемь действий:

1. **Проверка входа.** До разбиения: `n >= k`, различных значений в выборке не меньше `k`, и `estimator.supports(family)` истинно для каждого семейства (готовые распределения не проверяются, их не оценивают). Иначе `ValueError` или `NotImplementedError` со списком всех неподдерживаемых семейств, а не только первого: кластеризация, самая дорогая часть, не запускается зря.
2. **Разбиение.** Из `random_state` создаётся генератор `rng = np.random.default_rng(random_state)`, и `Assigner.assign(X, k, rng)` возвращает матрицу `H` размера `(n, k)`, где `k = len(families)`, и `ClusterInitializer` проверяет её структуру. Столбец `H` — один кластер. Затем столбцы переставляются по возрастанию среднего значения кластера: номера кластеров у назначателя произвольны (метки `KMeans` от запуска к запуску разные), а после сортировки столбец 0 — самый левый кластер.
3. **Таблица.** Создаётся пустая `ComponentTable(X, H, families, estimator)`.
4. **Сопоставление.** `Matcher.match(table)` возвращает перестановку `assignment`: элемент `families[j]` получает столбец `H[:, assignment[j]]`.
5. **Оценка.** Для каждого `j` компонента берётся из таблицы: `table.component(j, assignment[j])`. Если сопоставитель эту пару уже запрашивал, повторной оценки нет. Иначе таблица оценивает её сейчас: так бывает с `IdentityMatcher` и с `HungarianMatcher`, когда все семейства одинаковые и он к таблице не обращается.
6. **Веса.** Вес компоненты — средняя ответственность её кластера.
7. **Сборка.** Создаётся `MixtureModel(components, weights)`.
8. **Проверка результата.** `loglikelihood(X)` смеси должен быть конечен. Иначе `InitializationError` с примерами точек, которые не покрывает ни одна компонента. Так бывает, только когда раздачу выбрали, не глядя в таблицу: с `IdentityMatcher` и с `HungarianMatcher` при одинаковых семействах. Например, у `[expon, expon]` кластер `{−1, 5}` оценивается (`lambda_ = 0.5`), но точку −1 не покрывает ни одна компонента.

Изменяемого состояния вроде `PipelineState` нет: между стадиями передаются только `H`, таблица и `assignment`. Таблица меняется только как кэш: она запоминает уже посчитанные пары, и от порядка запросов её ответы не зависят. Порядок стадий фиксирован, поэтому `ClusterInitializer` принимает роли по имени, а не список шагов, как `Pipeline`.

### Шаг 1: назначение ответственностей

`Assigner.assign(X, n_components, rng)` разбивает выборку на `n_components` кластеров и возвращает матрицу `H` размера `(n, n_components)`. Назначатель не знает семейств: он видит только выборку и число компонент. Разбиение только жёсткое: в каждой строке `H` ровно одна единица, остальные нули, то есть каждая точка целиком принадлежит одному кластеру. На это опираются проверки кластеров, `min_cluster_size`, формулы вроде минимума и максимума для `ContinuousUniform` и поиск невозможных пар; почему мягкое разбиение пока не поддерживается, см. «Отложено».

Реализации:

- `SklearnAssigner(clusterer)` — обобщённый назначатель поверх любого кластеризатора scikit-learn — наследника `ClusterMixin`: `KMeans`, `MiniBatchKMeans`, `AgglomerativeClustering`, `SpectralClustering`, `Birch` и других. Передаёт выборку формой `(n, 1)`, как ждёт scikit-learn, и превращает метки в `H`. Число кластеров подставляет сам, см. ниже. Нужен scikit-learn: без него конструктор бросает `ImportError` с подсказкой поставить `pysatl-mpest[sklearn]`. Из кластеризаторов scikit-learn сверх k-means на одномерных данных полезны два: `AgglomerativeClustering` (детерминирован; со связью `single` режет по разрывам в данных и лучше k-means на модах разной ширины) и `MiniBatchKMeans` или `Birch` для очень больших выборок. Кластеризаторы, которые выбирают число кластеров сами (`DBSCAN`, `HDBSCAN`, `OPTICS`, `MeanShift`, `AffinityPropagation`), подходят плохо, см. ниже.
- `KMeansAssigner()` — k-means с инициализацией k-means++ на `scipy.cluster.vq.kmeans2`, без зависимостей сверх имеющихся. Генератор `rng` передаётся в `kmeans2` напрямую. Делает один запуск, а не лучший из нескольких, как `KMeans` из scikit-learn: несколько запусков даёт `MultiStartInitializer`. Пустой кластер `kmeans2` не исправляет, а только предупреждает; `ClusterInitializer` превращает его в `InitializationError`, и мультистарт такой запуск пропускает.
- `QuantileAssigner` — сортировка и разбиение на `n_components` отрезков с равным числом точек. Детерминирован.
- `RandomAssigner()` — случайное разбиение.

**Число кластеров берётся из `families`.** Перед каждым вызовом `SklearnAssigner` делает копию кластеризатора и, если у того есть параметр `n_clusters` (`KMeans`, `MiniBatchKMeans`, `AgglomerativeClustering`, `SpectralClustering`, `Birch`), ставит в копию `n_clusters=n_components`. Значение `n_clusters`, заданное пользователем в кластеризаторе, игнорируется: scikit-learn не отличает явно заданное значение от значения по умолчанию, поэтому правило одно и без исключений. Так один инициализатор работает с `families` любой длины, что нужно будущему `structure_selection`, который перебирает число компонент. Кластеризаторы без `n_clusters` (`DBSCAN`, `MeanShift`, `OPTICS`) число кластеров выбирают сами; для них назначатель проверяет, что различных меток ровно `n_components`, и иначе бросает `InitializationError`. Остальные назначатели берут число из `n_components`.

`GaussianMixture` не наследует `ClusterMixin` и через `SklearnAssigner` не подключается. Его естественное место — мягкое разбиение через `predict_proba`, которое пока не проектируется: позже это флаг или отдельный назначатель.

### Случайность

Случайность передаётся аргументом вызова, а не хранится в объектах. `initialize(X, families, random_state=None)` принимает `random_state` — `int`, `np.random.Generator` или `None`, как `MixtureModel.generate`. `ClusterInitializer` создаёт из него генератор `rng` и передаёт его в `assign(X, n_components, rng)`. Ни у одной роли нет поля со своим генератором, поэтому:

- одинаковые аргументы и одинаковый `random_state` дают одинаковую смесь, независимо от того, сколько раз объект вызывали раньше. Это нужно `structure_selection`: старт для одного числа компонент не зависит от того, перебирались ли до него другие;
- при `random_state=None` каждый вызов берёт свежую энтропию и не воспроизводится, как в numpy;
- детерминированный назначатель, например `QuantileAssigner`, аргумент `rng` не использует.

Кластеризаторы scikit-learn генератор не принимают: их `random_state` понимает только `int`, `None` и `RandomState`. Поэтому `SklearnAssigner` берёт из `rng` целое число и подставляет его в ту же копию кластеризатора, что и `n_clusters`, через `set_params(random_state=seed)`, если у того есть такой параметр. Исходный объект пользователя не меняется. `random_state`, заданный в самом кластеризаторе, игнорируется, как и `n_clusters`: иначе с `KMeans(random_state=0)` все запуски мультистарта давали бы одно и то же разбиение.

### Сопоставление кластеров и семейств

Кластеры, которые выдаёт шаг 1, не упорядочены. Если все семейства одинаковые, порядок не важен: любая раздача даёт ту же смесь с точностью до порядка компонент, а `MixtureModel.__eq__` от порядка не зависит. В гетерогенной смеси от раздачи зависит результат. Если отдать `Exponential` кластер с отрицательными точками, получится компонента с нулевым правдоподобием на этих точках.

**Когда семейства считаются одинаковыми.** Ключ семейства — тройка «имя семейства, параметризация, фиксированные параметры». Два `Normal` с фиксированными `mu=0` и `mu=5` — разные семейства, и сопоставление для них нужно.

**Таблица компонент.** Сопоставители работают с парами «семейство — кластер» через `ComponentTable`. `table.component(j, c)` возвращает компоненту семейства `families[j]`, оценённую на столбце $c$ матрицы `H` тем же `ComponentEstimator`, что и на шаге оценки; `table.loglikelihood(j, c)` — её логарифм правдоподобия $\ell_{jc}$ на этом кластере. Таблица ленивая: пару она оценивает при первом запросе и запоминает. Одинаковые семейства делят записи, поэтому при $d$ различных семействах оценок не больше $d \cdot k$, а не $k^2$. Известная компонента (готовое распределение) не оценивается: таблица возвращает её саму на любом кластере. Пару, которую оценщик компоненты оценить не смог (`EstimationError`), таблица запоминает как невозможную: `loglikelihood` для неё равен $-\infty$, а `component` снова бросает ту же ошибку, не вызывая оценщик компоненты повторно. `IdentityMatcher` к таблице не обращается и ничего не оценивает. Различаются сопоставители тем, какие пары они запрашивают и как по ним оценивают вариант раздачи. Пусть $\sigma(j)$ — столбец, отданный семейству $j$, $\gamma_{ic}$ — элементы `H`, $\hat\theta_{jc}$ — параметры компоненты из таблицы.

#### Критерий по парам: `HungarianMatcher`

Каждая пара «семейство — кластер» оценивается отдельно, как логарифм правдоподобия точек кластера при оценённой компоненте:

$$
\ell_{jc} = \sum_{i=1}^{n} \gamma_{ic} \log f_j\bigl(x_i \mid \hat\theta_{jc}\bigr).
$$

Вариант раздачи оценивается суммой по выбранным парам:

$$
\sigma^{*} = \arg\max_{\sigma \in S_k} \sum_{j=1}^{k} \ell_{j\sigma(j)}.
$$

Это классификационное правдоподобие при фиксированных кластерах. Сумма, а не среднее, потому что каждый кластер используется в любой раздаче ровно один раз, и сумма — это правдоподобие всей выборки при данной раздаче. Слагаемое с весами и штраф за число параметров от раздачи не зависят: вес едет вместе с кластером, а каждое семейство входит в смесь ровно один раз.

Критерий аддитивен: счёт пары не зависит от остальных пар. Поэтому задача — линейная задача о назначениях, и венгерский алгоритм (`scipy.optimize.linear_sum_assignment`) решает её точно за $O(k^3)$.

[Исходник схемы сопоставления](diagrams/initializers.drawio "Sequence: matching")

`HungarianMatcher` работает так:

- группирует одинаковые семейства. Если различное семейство одно, возвращает тождественную перестановку и ничего не оценивает;
- иначе запрашивает у таблицы $\ell_{fc}$ для каждого различного семейства и каждого кластера и строит стоимость `cost[f, c]` как $-\ell_{fc}$;
- размножает строки до матрицы `k × k`, по строке на каждый элемент `families`, и решает задачу назначений;
- внутри каждой группы одинаковых семейств переставляет доставшиеся ей кластеры по возрастанию номера столбца: строки группы в матрице стоимостей одинаковы, и `linear_sum_assignment` распределяет кластеры между ними произвольно. Сумма от этого не меняется, а порядок становится таким, как обещано в «Задаче».

**Невозможные пары.** У пары $\ell_{fc} = -\infty$ в двух случаях: точки кластера лежат вне носителя оценённой компоненты, или оценщик компоненты не смог её оценить, например `Exponential` на кластере с отрицательным средним даёт `lambda_ < 0`. Такая пара получает стоимость $+\infty$, и `linear_sum_assignment` её не выбирает: бесконечную стоимость он принимает как запрет. Если раздачи без запрещённых пар нет, scipy бросает `ValueError`, а сопоставитель вместо неё — `InitializationError` «нет раздачи, где каждое семейство получает подходящий кластер».

**Почему не жадный алгоритм.** Жадный берёт лучшую пару, вычёркивает её строку и столбец и повторяет. Ранний выбор может отнять у другого семейства единственный подходящий ему кластер:

| | A | B |
| --- | --- | --- |
| `Normal` | −100 | −110 |
| `Exponential` | −105 | −1000 |

Жадный выберет `Normal` ← A и получит в сумме −1100. Оптимум — `Normal` ← B, `Exponential` ← A, в сумме −215. В гетерогенных смесях это типично: `Normal` подходит почти к любому кластеру, а `Exponential` (или `Pareto`, когда он появится в `pysatl-core`) — только к «своему». Скорости жадный не даёт: ему нужна та же таблица, а время уходит на её заполнение, тогда как сам венгерский алгоритм на таблице $10 \times 10$ работает микросекунды.

#### Критерий по смеси: `ExhaustiveMatcher`

Позже, см. «Первая версия».

Вариант раздачи можно оценивать и правдоподобием всей смеси, собранной из оценённых компонент:

$$
\log L(\sigma) = \sum_{i=1}^{n} \log \sum_{j=1}^{k} \pi_{\sigma(j)} f_j\bigl(x_i \mid \hat\theta_{j\sigma(j)}\bigr).
$$

Этот критерий учитывает перекрытие компонент, но неаддитивен: логарифм стоит снаружи суммы по компонентам, поэтому вклад одной пары зависит от остальных. Венгерский алгоритм здесь не точен, и `ExhaustiveMatcher` перебирает раздачи. Перебираются только различимые, и внутри группы одинаковых семейств кластеры раздаются по возрастанию номера столбца: одинаковые семейства между собой не переставляются, поэтому вариантов

$$
\frac{k!}{m_1!\, m_2! \cdots m_d!},
$$

где $m_g$ — сколько раз встречается семейство $g$. Например, 5 `Normal` и 5 `Exponential` дают 252 варианта, а не $10!$. Таблица общая для всех вариантов, поэтому каждый вариант стоит одно вычисление $\log L$, то есть $O(nk)$. Раздачи с невозможной парой пропускаются; если не осталось ни одной, сопоставитель бросает `InitializationError`, как `HungarianMatcher`. Если вариантов больше `max_candidates`, сопоставитель бросает `ValueError`, а не уходит в долгий перебор молча: число вариантов зависит только от `families`, поэтому повтор с другим разбиением не поможет.

**Про AIC и BIC.** При выборе раздачи они не нужны. Число параметров смеси одинаково для всех раздач, поэтому AIC и BIC смеси отличаются от $-2 \log L(\sigma)$ на константу и выбирают ту же раздачу, что `ExhaustiveMatcher`. Сумма покомпонентных AIC по той же причине сводится к критерию `HungarianMatcher`, а как самостоятельный критерий качества модели некорректна: её штраф не учитывает, что разбиение тоже подобрано по данным. Информационные критерии нужны при сравнении разных структур смеси — это задача `structure_selection`.

#### `IdentityMatcher`

Возвращает `[0, 1, …, k-1]` и к таблице не обращается: компоненты для выбранных пар таблица оценит на шаге оценки. Невозможную пару он не обходит: её `EstimationError` прервёт `initialize` на шаге оценки. Нужен, когда порядок кластеров уже согласован с семействами, например для будущего кластеризатора, который сам учитывает семейства.

**Ускорение.** Пока не делается. Если таблица станет узким местом, ускорять нужно её заполнение, например считать $\ell_{fc}$ по подвыборке кластера. Это будет необязательный параметр сопоставителей или отдельная реализация.

### Шаг 2: оценка параметров компоненты

Известные компоненты (готовые распределения в `families`) этот шаг пропускают: у них оценивается только вес.

`ComponentEstimator` — способ оценки параметров компоненты по взвешенной выборке. Контракт роли:

- `supports(family)` сообщает, умеет ли способ оценивать пару «семейство, параметризация» этого семейства;
- `estimate(X, h, family)` по выборке и весам точек `h` (столбец `H`) оценивает свободные параметры и возвращает `ParametricFamilyDistribution`. Для неподдерживаемого семейства бросает `NotImplementedError`.

Способ оценки — законная ось расширения модуля:

- `MLEEstimator` — взвешенная оценка максимального правдоподобия в явном виде, без оптимизации. У каждого семейства свои формулы в реестре по паре «семейство, параметризация». Для `Normal` и `Exponential` она совпадает с методом моментов. Для `ContinuousUniform` это минимум и максимум кластера. Для семейств, которых в `pysatl-core` пока нет: у `Laplace` — взвешенная медиана и среднее абсолютное отклонение от неё, у `LogNormal` — среднее и стандартное отклонение логарифмов. Где формулы есть у обоих способов, MLE обычно точнее моментов: у `ContinuousUniform` и `Laplace` заметно. В первой версии формулы есть для `Normal` (`meanStd`), `Exponential` (`rate`) и `ContinuousUniform` (`standard`).
- `MomentsEstimator` — взвешенный метод моментов, тоже со своим реестром формул. Позже, см. «Первая версия».
- `EstimatorChain(estimators)` — позже, см. «Первая версия». Упорядоченный список способов. Для каждого семейства берётся первый способ, у которого `supports(family)` истинно. Если не подходит ни один, `estimate` бросает `NotImplementedError` с перечнем опробованных способов.

**Формула** — функция в реестре `MLEEstimator` или `MomentsEstimator` для пары «семейство, параметризация»: `formula(X, h, fixed) -> dict`. Она получает выборку, веса точек `h` (столбец `H`) и `fixed` — параметры, зафиксированные через `view` (пустой словарь для обычного семейства), и возвращает только свободные параметры. Фиксированные значения она обязана использовать в расчёте: у `normal.view(mu=0)` на кластере `{4, 5, 6}` `sigma` считается как разброс вокруг 0, около 5.07, а не вокруг среднего 5. Оценщик компоненты находит формулу по паре, берёт `fixed` у семейства, вызывает формулу и собирает компоненту `family.distribution(**free)`. Если формула вернула бы и фиксированный параметр с другим значением, `pysatl-core` не дал бы создать распределение. В `MomentsEstimator` уравнений берётся столько, сколько свободных параметров, начиная с первого момента; фиксированные параметры подставляются в теоретические моменты как известные.

`EstimatorChain` заодно решает выбор способа под семейство: если формулы для семейства есть у нескольких способов, выигрывает тот, что стоит в списке раньше. Например, `EstimatorChain([MLEEstimator(), MomentsEstimator()])` оценит формулами MLE всё, для чего они есть, а остальное — моментами. Выбор идёт по семейству, а не по номеру компоненты: два одинаковых семейства оцениваются одним способом. Это согласовано с сопоставлением, которое тоже группирует одинаковые семейства.

Стратегии M-шага из `estimators.iterative._strategies` не переиспользуются. Они приватные и работают с `PipelineState` и компонентой, у которой параметры уже заданы, а на шаге 2 параметров ещё нет. Формулы для `Normal` и `Exponential` по сути совпадают с теми, что есть в M-шаге, но в `initializers` живут отдельно. Общий диспетчер по ключу «имя семейства, параметризация» и общие формулы позже можно вынести в модуль вне `initializers` и `estimators` — это отдельная задача: формулы M-шага обновляют только часть параметров и при вырожденной дисперсии сохраняют старое значение, поэтому к чистой `formula(X, h, fixed)` они сводятся рефакторингом `estimators`.

### Веса

Вес компоненты $j$ — средняя ответственность её кластера:

$$
\pi_j = \frac{1}{n} \sum_{i=1}^{n} \gamma_{i\sigma(j)}.
$$

Правило одно и не зависит от ролей, поэтому отдельной роли для весов нет. Известная компонента получает вес так же, по своему кластеру.

### Вырожденные кластеры

Параметры не удаётся оценить не только по пустому кластеру, но и по любому вырожденному:

- **пустой кластер** — у кластеризатора центр остался без точек, у случайного разбиения при малом `n` кластер не получил точек;
- **слишком мало точек** — например, кластер из одной точки;
- **нет разброса** — кластер целиком из одинаковых значений, частый случай при повторах в выборке. У `Normal` получится `sigma = 0`, и `pysatl-core` не даст создать такое распределение.

Ответственность разделена так:

- **Назначатель и `ClusterInitializer` проверяют только структуру разбиения.** `KMeans` из scikit-learn сам переносит центры опустевших кластеров, `kmeans2` и остальные кластеризаторы этого не делают, и мы их не чиним. `SklearnAssigner` проверяет метки: их ровно `n_components`, нет «шумовых» меток (`-1` у DBSCAN). `ClusterInitializer` проверяет `H` от любого назначателя. Форма — `(n, k)` и каждая строка — ровно одна единица среди нулей; иначе `ValueError`: это ошибка в назначателе, и другое разбиение её не исправит. Пустых столбцов нет; иначе `InitializationError`. Если `n < k` или различных значений в выборке меньше `k`, сразу `ValueError`, до разбиения: это ошибка входа, а не неудачное разбиение.
- **Достаточность данных проверяет оценщик компоненты.** Сколько данных нужно, знает только способ оценки: назначатель не видит ни семейств, ни формул. Нижняя граница вычислимости — различных значений в кластере не меньше, чем свободных параметров: иначе условий меньше, чем неизвестных. Например, `MomentsEstimator` для `Normal` требует хотя бы двух различных значений, иначе `sigma = 0`. Если по формулам получаются недопустимые параметры (`sigma = 0`, `lambda_ < 0`) или данных не хватает, оценщик компоненты бросает `EstimationError` с номером кластера и семейством, а не `ValueError` из глубины `pysatl-core`. На шаге сопоставления такая пара просто становится невозможной, см. «Невозможные пары». В `EstimatorChain` `EstimationError` не передаёт кластер следующему способу: иначе одинаковые семейства могли бы оказаться оценены разными способами, а `supports(family)` отвечает только на вопрос, есть ли формулы.
- **Порог качества — по желанию пользователя.** Необязательный параметр `ClusterInitializer(min_cluster_size=...)`, по умолчанию выключен. Кластер меньше порога делает запуск неудачным (`InitializationError`); с `MultiStartInitializer` такие разбиения просто отбрасываются. Порог по умолчанию не зашит, потому что «достаточно точек для старта» — вопрос вкуса, а не корректности.
- **Никаких молчаливых подстановок** вроде «взять оценку по всей выборке»: такая смесь выглядит нормально, но построена не так, как думает пользователь.
- **Повторные попытки** — дело `MultiStartInitializer`, а не отдельной логики внутри.

### Ошибки

Ошибки инициализатора делятся на два вида, и ловятся по-разному.

- **Неудачное разбиение** — `InitializationError` и его наследник `EstimationError`. Разбиение не подошло: пустой или слишком маленький кластер, пара «семейство — кластер», которую нельзя оценить, нет допустимой раздачи, смесь не покрывает часть выборки. Другое разбиение может пройти, поэтому такие ошибки ловят таблица (только `EstimationError`, на сопоставлении) и `MultiStartInitializer`.
- **Всё остальное** пробрасывается без перехвата: ошибки входа (`ValueError`: `n < k`, слишком много вариантов у `ExhaustiveMatcher`), неподдерживаемое семейство (`NotImplementedError`, проверяется до разбиения), ошибки в коде. Повтор с другим разбиением их не исправит, а перехват спрятал бы настоящую проблему.

### Мультистарт

`MultiStartInitializer(initializer, n_init)` вызывает `initializer.initialize(X, families, random_state=child)` `n_init` раз, каждый раз со своим генератором `child`, считает `loglikelihood(X)` каждой смеси и возвращает смесь с наибольшим значением.

- **Разные результаты при повторах.** Обёртка создаёт генератор из своего `random_state` и делит его на `n_init` независимых генераторов через `rng.spawn(n_init)`. Каждый запуск получает свой, поэтому запуски различаются, воспроизводятся при одном `random_state` и не зависят друг от друга: их можно выполнять параллельно.
- **Ошибки отдельных запусков.** Если запуск упал с `InitializationError`, например на вырожденном кластере, обёртка пропускает его. Другие ошибки она не ловит, см. «Ошибки». Ошибку она бросает, только если упали все запуски, и прикладывает причину последнего. Так мультистарт заодно закрывает редкие вырожденные разбиения.
- **С детерминированным инициализатором** (например, с `QuantileAssigner`) мультистарт бесполезен: все запуски одинаковы.
- **Критерий — правдоподобие стартовой смеси,** а не результат EM. Это дёшево, но лучший старт не обязательно приводит к лучшему итогу. Вариант «прогнать каждого кандидата несколькими итерациями EM» (emEM) — отдельный будущий инициализатор.

## Как расширить

- **Кластеризатор scikit-learn.** Поставить `pysatl-mpest[sklearn]` и передать кластеризатор в `SklearnAssigner`.
- **Назначатель.** Унаследовать `Assigner` и реализовать `assign`: вернуть матрицу `(n, n_components)`, в каждой строке которой ровно одна единица, остальные нули. Случайность брать только из аргумента `rng`, не хранить генератор в объекте.
- **Формулы для нового семейства.** Зарегистрировать функцию `formula(X, h, fixed) -> dict` для пары «семейство, параметризация» в реестре нужного способа, например `MLEEstimator` или `MomentsEstimator`. Она должна учитывать `fixed` и возвращать только свободные параметры.
- **Новый способ оценки.** Унаследовать `ComponentEstimator`, реализовать `supports` и `estimate` и поставить способ в нужное место `EstimatorChain`. Если по данным кластера параметры не получаются, бросать `EstimationError`. Способ в явном виде можно добавлять в цепочку по умолчанию, численный — нет.
- **Сопоставитель.** Унаследовать `Matcher` и реализовать `match`: вернуть перестановку длины `k`. Компоненты и $\ell_{jc}$ брать из переданной `ComponentTable`, а не оценивать заново.
- **Инициализатор другого устройства.** Унаследовать `Initializer` напрямую; мультистарт с ним работает без изменений.

## Ограничения и решения

Ограничения проекта:

- Назначатель не знает семейств. Для смесей с разными носителями (например, `Normal` и `Exponential`) кластеры могут не подойти ни одному семейству. Сопоставление выбирает лучшую из возможных пар, но не исправляет разбиение.
- Назначатель не учитывает фиксированные параметры. Обычно это исправляет сопоставление: у `[normal.view(mu=0), normal]` на модах около 0 и около 10 семейство с `mu=0` получит кластер около 0, потому что на другом кластере его правдоподобие хуже. Но если ни один кластер не лежит около зафиксированного значения, например широкая компонента вокруг 0 и узкая около 3 дают кластеры около −3 и 3, стартовая `sigma` у `normal.view(mu=0)` будет смещена. Исправляют это EM, запущенный из полученной смеси (фиксированный `mu` там тоже держится), или мультистарт с другим разбиением.
- Формулы оценки регистрируются по параметризации. У `Normal` их четыре (`meanStd`, `meanVar`, `meanPrec`, `exponential`), а преобразования из базовой параметризации в другую в `pysatl-core` нет, поэтому формулы `meanStd` для `meanVar` не переиспользовать. `normal.view(parametrization_name="meanVar")` с цепочкой по умолчанию даст `NotImplementedError` на проверке входа, пока для `meanVar` не зарегистрированы свои формулы.
- Оба критерия сопоставления считаются в точке оценки `ComponentEstimator`, а не в максимуме правдоподобия. Сопоставление оптимально только относительно оценок выбранного способа.
- Число вариантов у `ExhaustiveMatcher` растёт комбинаторно: при многих разных семействах он неприменим.
- Семейство без формул в явном виде пока инициализировать нельзя: численного способа оценки нет, он отложен (см. «Принятые решения»).
- Только жёсткое разбиение и только одномерные выборки.

Принятые решения:

- **Имя метода** — `initialize(X, families, random_state=None)`.
- **Случайность** — аргумент вызова: `random_state` у `initialize`, `rng` у `assign`; у ролей нет своего генератора, мультистарт делит генератор через `spawn`.
- **Тип элемента `families`** — `ParametricFamily | ParametricFamilyDistribution`; свой тип — когда появятся настройки отдельной компоненты.
- **Порядок одинаковых семейств** — по возрастанию среднего их кластеров: `ClusterInitializer` сортирует столбцы `H`, сопоставители раздают кластеры внутри группы в порядке столбцов.
- **Разбиение** — роль `Assigner`, только жёсткое: `H` из единиц и нулей, по одной единице в строке, это проверяет `ClusterInitializer`; k-means по умолчанию — `KMeansAssigner` на `scipy.cluster.vq.kmeans2`, своего k-means нет; остальные кластеризаторы scikit-learn — через `SklearnAssigner`, scikit-learn — необязательная зависимость (`pysatl-mpest[sklearn]`). Число кластеров `SklearnAssigner` берёт из `families` и подставляет в копию кластеризатора, `n_clusters` пользователя игнорируется. Назначатель передаётся явно, по умолчанию его нет.
- **Вырожденные кластеры** — назначатель и `ClusterInitializer` проверяют структуру разбиения, оценщик компоненты — достаточность данных для своих формул; необязательный `min_cluster_size`; никаких подстановок, повторы через мультистарт.
- **Мультистарт** — обёртка `MultiStartInitializer` поверх любого `Initializer`.
- **Ошибки** — `InitializationError` для неудачного разбиения и наследник `EstimationError` для пары, которую нельзя оценить. Невозможная пара не обрывает сопоставление, а исключается из раздач; ловятся только эти два типа.
- **Таблица компонент** — ленивый кэш `ComponentTable`, общий для сопоставления и шага оценки: каждая пара «семейство — кластер» оценивается не больше одного раза при любом сопоставителе.
- **Способы оценки** — в первой версии только `MLEEstimator` (он же по умолчанию); `MomentsEstimator`, `EstimatorChain` и `ExhaustiveMatcher` — позже, с первым случаем, где они нужны.
- **Контракт формулы** — `formula(X, h, fixed) -> dict` свободных параметров; фиксированные параметры входят аргументом.
- **Диспетчеризация по семейству** — свой диспетчер в `initializers`, ключ берётся у семейства, а не у компоненты; общий диспетчер и общие формулы с M-шагом — отдельной задачей.
- **Отложено:** назначатель, учитывающий семейства, например k-means с неподвижными центрами для фиксированных параметров положения, в паре с `IdentityMatcher` (нужно передать `families` в `assign`; помогает только параметрам положения); численный способ оценки через `Optimizer` (оптимизатору нужна начальная точка, а у семейства без формул её взять неоткуда; решается вместе с первым таким семейством); мягкое разбиение (при нём почти каждая точка имеет вес в каждом кластере, поэтому нужно заново определить: какой вес считать принадлежностью к кластеру, размер кластера для проверок и `min_cluster_size`, носитель и невозможные пары, границы `ContinuousUniform`; `estimate(X, h, family)` уже принимает веса и меняться не будет); способ оценки по L-моментам (устойчивее к выбросам, подходит для GEV, Gumbel, Pareto, но строится по порядковым статистикам и требует решить, как работать с мягким разбиением); ускорение сопоставления подвыборкой.
