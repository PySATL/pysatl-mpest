# Оценка параметров компоненты
**Назначение:** описать роль `ComponentEstimator` модуля [`initializers`](../initializers.md): как параметры одной компоненты оцениваются по точкам кластера и как устроены формулы (Запланировано).

Оценщик компоненты вызывается только из {ref}`таблицы компонент <init-component-table>` и только считает числа. Компоненту из них собирает и проверяет `evaluate_pair`, одинаково для любого оценщика, см. {ref}`«Оценка пары» <init-pair-walk>`.

## Контракт

- `supports(family)` — умеет ли способ оценивать пару «семейство, параметризация»;
- `estimate(X, h, family) -> dict[str, float]` — свободные параметры по выборке и маске кластера `h` (столбец `H`: 1.0 у точек кластера, 0.0 у остальных);
- неподдерживаемое семейство — `NotImplementedError`;
- данных не хватает формулам способа — `ComponentEstimationError` с причиной, см. {ref}`«Достаточность данных» <init-degenerate>`.

Остальное проверяет `evaluate_pair`: ключи — ровно свободные параметры; различных значений не меньше, чем параметров; значения — конечные вещественные скаляры; параметры допустимы; компонента не вырождена и, временно, выше порогов M-шага. Поэтому свой способ — это «данные кластера → словарь чисел», и забыть проверку в нём нельзя.

| Способ | Что делает | Статус |
| --- | --- | --- |
| `MLEComponentEstimator` | MLE в явном виде, без оптимизации; свои формулы на пару «семейство, параметризация» | Первая версия: `Normal` (`meanStd`), `Exponential` (`rate`), `ContinuousUniform` (`standard`) |
| `MomentsComponentEstimator` | Метод моментов по сегменту (INIT-05), свой реестр формул | Позже, см. {ref}`«Первая версия» <init-first-version>` |
| `ComponentEstimatorChain(estimators)` | Для каждого семейства — первый способ из списка, у которого `supports(family)` истинно | Позже, см. {ref}`«Первая версия» <init-first-version>` |

- **MLE:** у `Normal` и `Exponential` совпадает с моментами, у `ContinuousUniform` — минимум и максимум кластера; будущие `Laplace` — медиана и среднее абсолютное отклонение, `LogNormal` — моменты логарифмов. Где есть оба способа, MLE обычно точнее (заметно у `ContinuousUniform` и `Laplace`).
- **Моменты:** уравнений столько, сколько свободных параметров, начиная с первого момента; фиксированные параметры подставляются как известные.
- **Цепочка:** `ComponentEstimatorChain([MLEComponentEstimator(), MomentsComponentEstimator()])` оценит формулами MLE всё, для чего они есть, остальное — моментами. Не подошёл ни один — `NotImplementedError` с перечнем способов. Выбор — по семейству, а не по номеру компоненты: одинаковые семейства оцениваются одним способом.

## Ход `estimate`

`MLEComponentEstimator.estimate(X, h, family)`:

1. Находит формулу по имени и параметризации — первым двум элементам `_components.family_key(family)`. Фиксированные параметры в ключ реестра не входят: одна формула обслуживает `normal` и `normal.view(mu=0)`.
2. Берёт фиксированные параметры через `_components.family_fixed_parameters(family)`.
3. Вызывает `formula(X, h, fixed)` и возвращает её словарь без изменений.

Номеров семейства и кластера не знают ни оценщик, ни `evaluate_pair`: их добавляет к причине таблица.

## Контракт формулы

**Формула** — функция в реестре способа для пары «семейство, параметризация»: `formula(X, h, fixed) -> dict[str, float]`, где `fixed` — параметры из `view` (пустой словарь у обычного семейства).

- **Точки кластера — через `h > 0`, а не `X[h]`;** взвешенные статистики — через `weights=h`. `h` — `float64`, и `X[h]` бросает `IndexError`; правило годится и для будущих дробных весов.
- **Учитывает фиксированные значения:** у `normal.view(mu=0)` на кластере `{4, 5, 6}` `sigma` — разброс вокруг 0, около 5.07, а не вокруг среднего 5.
- **Возвращает только свободные параметры,** даже если фиксированный совпадает по значению. Лишний или недостающий ключ `evaluate_pair` отвергает `TypeError` до сборки компоненты: это ошибка в формуле, а не в данных. Иначе `pysatl-core` 0.1.0a0 падал бы по-разному: `ValueError` «Parameter 'mu' is fixed to 0, but got 5.0» (неотличим от нарушенного ограничения) или `TypeError` «unexpected keyword arguments: 'mu'» ([pysatl-core#159](https://github.com/PySATL/pysatl-core/issues/159)).
- **Может бросить `ComponentEstimationError`,** если данных не хватает сверх общей нижней границы.
- **Может искать один корень** `scipy.optimize.brentq` на отрезке, если параметр формы не выражается явно: у `Weibull` по моментам $\Gamma(1+2/k)/\Gamma(1+1/k)^2 = 1 + \mathrm{CV}^2$, у `Gamma` по MLE $\ln k - \psi(k) = \ln \bar x - \overline{\ln x}$. Начальная точка не нужна, нужны отрезок со сменой знака и монотонность — их обеспечивает формула; нет корня — `ComponentEstimationError`. Многомерная оптимизация внутри формулы не допускается.

## Реестр формул

- **Приватный, один на способ, на уровне модуля,** как `FamilyDispatch` у стратегий M-шага. Формулы для новых семейств `pysatl-core` добавляет библиотека; пользователь расширяет способ через `ComponentEstimator`, публичной регистрации нет. Ключ — имя и параметризация семейства.
- **Регистрация вызовом при импорте,** а не декоратором: `mutmut` не мутирует декорированные функции. Тесты диспетчера создают свой экземпляр.
- **Свой диспетчер, `_dispatch.py`,** берёт ключ у семейства через `_components.family_key`. `FamilyDispatch` из `estimators` не подходит: он берёт ключ у готовой компоненты, которой при оценке по кластеру ещё нет, и лежит в приватном модуле `estimators`. Общий диспетчер в `core` — отдельной задачей ([#52](https://github.com/PySATL/pysatl-mpest/issues/52)), см. {ref}`«Отложено» <init-deferred>`.
- **Стратегии M-шага не переиспользуются:** они приватные, работают с `PipelineState` и компонентой с заданными параметрами, обновляют только часть параметров и при вырожденной дисперсии сохраняют старое значение. Формулы `Normal` и `Exponential` по сути совпадают, но живут отдельно; общие формулы — позже, рефакторингом `estimators`.
