# Оценка параметров компоненты
**Назначение:** описать роль `ComponentEstimator` модуля [`initializers`](../initializers.md): как параметры одной компоненты оцениваются по точкам кластера и как устроены формулы (Запланировано).

Оценщик компоненты вызывается только из {ref}`таблицы компонент <init-component-table>`: когда сопоставитель или сборка смеси запрашивает пару «семейство — кластер». Он только считает числа. Компоненту из них собирает и проверяет таблица, одинаково для любого оценщика, см. {ref}`«Оценка пары» <init-pair-walk>`.

## Контракт

`ComponentEstimator` — способ оценки параметров компоненты по точкам кластера. Контракт роли:

- `supports(family)` сообщает, умеет ли способ оценивать пару «семейство, параметризация» этого семейства;
- `estimate(X, h, family) -> dict[str, float]` по выборке и маске кластера `h` (столбец `H`, `UnivariateFloatArray`: 1.0 у точек кластера, 0.0 у остальных) оценивает свободные параметры и возвращает их словарём `{имя: значение}`;
- для неподдерживаемого семейства `estimate` бросает `NotImplementedError`;
- если данных кластера не хватает для оценки, `estimate` бросает `ComponentEstimationError` с причиной, см. {ref}`«Достаточность данных» <init-degenerate>`.

Остальное оценщику проверять не нужно, это делает таблица:

- что ключи словаря — ровно свободные параметры семейства;
- что значения конечны;
- что параметры допустимы для параметризации;
- что компонента не вырождена численно.

Поэтому свой способ оценки пишется как «данные кластера → словарь чисел», и забыть в нём проверку нельзя.

Способ оценки — законная ось расширения модуля:

| Способ | Что делает | Статус |
| --- | --- | --- |
| `MLEComponentEstimator` | Оценка максимального правдоподобия в явном виде, без оптимизации; свои формулы на каждую пару «семейство, параметризация» | Первая версия: формулы для `Normal` (`meanStd`), `Exponential` (`rate`) и `ContinuousUniform` (`standard`) |
| `MomentsComponentEstimator` | Метод моментов, тоже со своим реестром формул | Позже, см. {ref}`«Первая версия» <init-first-version>` |
| `ComponentEstimatorChain(estimators)` | Упорядоченный список способов; для каждого семейства берётся первый, у которого `supports(family)` истинно | Позже, см. {ref}`«Первая версия» <init-first-version>` |

- **Формулы MLE.** Для `Normal` и `Exponential` они совпадают с методом моментов. Для `ContinuousUniform` это минимум и максимум кластера. Для семейств, которых в `pysatl-core` пока нет: у `Laplace` — медиана и среднее абсолютное отклонение от неё, у `LogNormal` — среднее и стандартное отклонение логарифмов. Где формулы есть у обоих способов, MLE обычно точнее моментов: у `ContinuousUniform` и `Laplace` заметно.
- **Метод моментов.** Уравнений берётся столько, сколько свободных параметров, начиная с первого момента. Фиксированные параметры подставляются в теоретические моменты как известные.
- **Цепочка выбирает способ под семейство.** Если формулы для семейства есть у нескольких способов, выигрывает тот, что стоит в списке раньше. Например, `ComponentEstimatorChain([MLEComponentEstimator(), MomentsComponentEstimator()])` оценит формулами MLE всё, для чего они есть, а остальное — моментами. Если не подходит ни один способ, `estimate` бросает `NotImplementedError` с перечнем опробованных способов.
- **Выбор идёт по семейству, а не по номеру компоненты:** два одинаковых семейства оцениваются одним способом. Это согласовано с сопоставлением, которое тоже группирует одинаковые семейства.

## Ход `estimate`

`MLEComponentEstimator.estimate(X, h, family)`:

1. Находит формулу в реестре по ключу `_components.family_key(family)`.
2. Берёт фиксированные параметры семейства через `_components.family_fixed_parameters(family)`.
3. Вызывает формулу `formula(X, h, fixed)` и возвращает её словарь свободных параметров `free` без изменений.

Как таблица проверяет `free` и собирает из него компоненту, показано на схеме {ref}`«Оценка пары» <init-pair-walk>`. Номеров семейства и кластера оценщик не знает: их добавляет к причине таблица.

## Контракт формулы

**Формула** — функция в реестре `MLEComponentEstimator` или `MomentsComponentEstimator` для пары «семейство, параметризация»: `formula(X, h, fixed) -> dict[str, float]`.

- **Получает** выборку, маску кластера `h` (столбец `H`) и `fixed` — параметры, зафиксированные через `view`; для обычного семейства это пустой словарь.
- **Точки кластера выбирает через `h > 0`, а не `X[h]`;** взвешенные статистики считает через `weights=h`. `h` — массив `float64`, и `X[h]` на нём бросает `IndexError`. Правило работает и для будущего мягкого разбиения, и для общих с M-шагом формул, у которых веса дробные.
- **Обязана использовать фиксированные значения** в расчёте: у `normal.view(mu=0)` на кластере `{4, 5, 6}` `sigma` считается как разброс вокруг 0, около 5.07, а не вокруг среднего 5.
- **Возвращает только свободные параметры.** Фиксированные параметры формула не возвращает никогда, даже с тем же значением. Таблица сверяет ключи до сборки компоненты и на лишнем или недостающем ключе бросает `TypeError`: это ошибка в формуле, а не в данных, и в `ComponentEstimationError` она не переводится. Поэтому фиксированный параметр в `pysatl-core` не попадает. `pysatl-core` 0.1.0a0 на нём падал бы по-разному: на другое значение — `ValueError` «Parameter 'mu' is fixed to 0, but got 5.0», а на то же — `TypeError` «unexpected keyword arguments: 'mu'» ([pysatl-core#159](https://github.com/PySATL/pysatl-core/issues/159)). Первый из них неотличим от `ValueError` нарушенного ограничения параметризации.
- **Может бросить `ComponentEstimationError`,** если по данным кластера параметры не получаются, например различных значений меньше, чем свободных параметров.
- **Временная проверка у `Normal`.** Формулы `Normal` бросают `ComponentEstimationError`, если дисперсия кластера не больше `NUMERICAL_TOLERANCE` M-шага (`1e-9`), с причиной «дисперсия меньше абсолютного порога M-шага `1e-9`, перемасштабируйте данные». Почему, см. {ref}`«Численная вырожденность» <init-degenerate>`.

## Реестр формул

- **Приватный и один на способ оценки,** на уровне модуля, как `FamilyDispatch` у стратегий M-шага в `estimators`. Все семейства берутся из `pysatl-core`, и формулу для нового семейства добавляет сама библиотека, а не пользователь. Публичной регистрации формул нет: пользователь расширяет способ оценки через `ComponentEstimator`.
- **Регистрация вызовом при импорте,** а не декоратором: `mutmut` не мутирует декорированные функции. Тесты диспетчера создают собственный экземпляр и глобальный реестр не трогают.
- **Свой диспетчер, `_dispatch.py`.** Он выбирает формулу по паре «имя семейства, параметризация» из `_components.family_key` самого семейства. Это не копия `FamilyDispatch` из `estimators.iterative._strategies`: тот берёт ключ у готовой компоненты, а при оценке по кластеру компоненты ещё нет. Импортировать его нельзя, иначе `initializers` зависел бы от `estimators`.

**Стратегии M-шага не переиспользуются.** Стратегии из `estimators.iterative._strategies` приватные и работают с `PipelineState` и компонентой, у которой параметры уже заданы, а при оценке по кластеру параметров ещё нет. Формулы для `Normal` и `Exponential` по сути совпадают с теми, что есть в M-шаге, но в `initializers` живут отдельно. Общий диспетчер по ключу «имя семейства, параметризация» и общие формулы позже можно вынести в модуль вне `initializers` и `estimators`. Это отдельная задача: формулы M-шага обновляют только часть параметров и при вырожденной дисперсии сохраняют старое значение, поэтому к чистой `formula(X, h, fixed)` они сводятся рефакторингом `estimators`.
