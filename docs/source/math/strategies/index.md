## Что такое стратегия

`MaximizationStep` обновляет параметры компонент по блокам `OptimizationBlock`. Блок задаёт компоненту, набор её параметров и стратегию из перечисления `MaximizationStrategy`. Стратегия — функция, которая по текущему состоянию конвейера вычисляет новые значения параметров блока. Каждая стратегия максимизирует свою целевую функцию:

| Стратегия | Целевая функция | Что читает | Где используется | Гарантия монотонности |
|---|---|---|---|---|
| [`QFUNCTION`](q_function.md) | слагаемое $Q$ одной компоненты {eq}`eq-em-component` | свою компоненту и столбец $\gamma_{\cdot j}$ | `EM`, `ECM`, `ECME` | да, теорема {prf:ref}`thm-gem-monotone` |
| [`OBSERVED_DATA_LIKELIHOOD`](observed_data_likelihood.md) | $\ln L$ {eq}`eq-observed-loglik` по параметрам одной компоненты | все компоненты и веса | `ECME` | отдельный шаг не уменьшает $\ln L$; итерация ECME — при Q-шагах раньше L-шагов, теорема {prf:ref}`thm-ecme-monotone` |
| [`MOMENTS`](moments.md) | равенство взвешенных и теоретических моментов, эвристика | свою компоненту и столбец $\gamma_{\cdot j}$ | ни один оценщик; только в `Pipeline`, собранном вручную | нет в общем случае |

## Выбор реализации по семейству

Стратегия — не одна функция, а диспетчер `FamilyDispatch`. Он выбирает реализацию по паре «{term}`семейство <Семейство>`, {term}`параметризация <Параметризация>`» компоненты и, если для пары ничего не зарегистрировано, вызывает реализацию по умолчанию:

| Стратегия | (`Normal`, `meanStd`) | (`Exponential`, `rate`) | Остальные пары |
|---|---|---|---|
| `QFUNCTION` | {ref}`в явном виде <math-q-normal>` | {ref}`в явном виде <math-q-exponential>` | численная оптимизация |
| `OBSERVED_DATA_LIKELIHOOD` | численная оптимизация | численная оптимизация | численная оптимизация |
| `MOMENTS` | {ref}`в явном виде <math-moments-normal>` | {ref}`в явном виде <math-moments-exponential>` | `NotImplementedError` |

Чтобы новая пара получила решение в явном виде, его выводят из целевой функции стратегии и регистрируют через `register` у соответствующего диспетчера.

## Что читает стратегия

Любой блок записывает только параметры своей компоненты. Читает же стратегия разное, и от этого зависит, какие блоки `MaximizationStep` может вычислять вместе. Таблица `STRATEGY_ACCESS` в коде фиксирует два варианта:

- **`OWN_COMPONENT`** — стратегия читает только свою компоненту, выборку и ответственности. Так устроены `QFUNCTION` и `MOMENTS`: их целевая функция для компоненты $j$ зависит только от $\theta_j$, выборки и столбца ответственностей $\gamma_{\cdot j}^{(t)}$, который на M-шаге не меняется. Обоснование для `QFUNCTION` — разложение {eq}`eq-q-split`.
- **`ALL_COMPONENTS`** — стратегия читает все компоненты и веса. Так устроена `OBSERVED_DATA_LIKELIHOOD`: условие максимума правдоподобия по $\theta_q$ зависит от вклада остальных компонент в плотность смеси, это показано в {ref}`выводе градиента <math-odl-gradient>`.

Блоки `OWN_COMPONENT` разных компонент не читают того, что пишут друг другу, поэтому их можно вычислить из одного снимка смеси в любом порядке. Блок `ALL_COMPONENTS` должен видеть результаты всех блоков, стоящих перед ним в списке, поэтому идёт после них.
