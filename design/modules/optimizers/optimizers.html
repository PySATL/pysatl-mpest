Модуль optimizers#

Назначение: объяснить, где в оценке смеси нужна численная оптимизация, какой контракт должен выполнять оптимизатор и как подключить свой.

Состав модуля#

Модуль экспортирует три класса — Optimizer, ScipyNelderMead и ScipyPowell:

  • optimizer.py — абстрактный Optimizer с единственным методом minimize(target, params).

  • scipy_nelder_mead.py — ScipyNelderMead, симплекс-метод Нелдера — Мида из scipy.optimize.minimize.

  • scipy_powell.py — ScipyPowell, метод сопряжённых направлений Пауэлла из scipy.optimize.minimize.

Модуль не зависит от core и estimators: оптимизатор получает только целевую функцию и начальную точку и ничего не знает о смесях.

Диаграмма классов#

Лист Overview показывает иерархию оптимизаторов, классы estimators, которые их хранят и вызывают, и функцию scipy, на которой они построены.

Исходник диаграммы классов

  • EM, ECM и ECME принимают оптимизатор в конструкторе и передают его в MaximizationStep, тот — стратегиям M-шага.

  • minimize вызывают две приватные стратегии из _strategies: observed_data_likelihood_strategy и q_function_strategy. Последняя обращается к оптимизатору только для семейств без аналитического решения; оно есть для Normal с параметризацией meanStd и Exponential с параметризацией rate. moments_strategy получает оптимизатор, но не использует.

  • Если в блоке M-шага нет параметров для обновления, стратегия возвращается раньше и оптимизатор не вызывается.

  • Оба наследника вызывают scipy.optimize.minimize с соответствующим method и настройками scipy по умолчанию.

Контракт minimize#

minimize(target, params) получает целевую функцию от вектора параметров и начальную точку и возвращает точку, в которой цель меньше. Стратегии M-шага задают цель так:

  • Параметры оптимизируются без ограничений. Если точка нарушает ограничения параметризации, например отрицательный масштаб, цель возвращает +inf. Реализация должна выдерживать такие значения.

  • Начальная точка — текущие значения обновляемых параметров компоненты, поэтому оптимизация продолжается с результата прошлой итерации.

Оптимизатор не сообщает, сошёлся ли он: возвращается лучшая найденная точка. MaximizationStep применяет её как есть. Если точка нарушает ограничения параметризации, пересборка компоненты бросает ValueError, и fit прерывается с этим исключением. Поэтому реализация должна возвращать точку, где цель конечна, например не хуже начальной.

Выбор оптимизатора#

Оба метода не используют производные, поэтому подходят для любых семейств pysatl-core.

Оптимизатор

Особенности

ScipyNelderMead

Не ухудшает цель относительно начальной точки. На это опирается гарантия ECME: при мягких ответственностях и без удаления компонент правдоподобие наблюдаемых данных не убывает между итерациями.

ScipyPowell

На время оптимизации подавляет предупреждения NumPy о недопустимых значениях (invalid). Неухудшение цели для него в коде не заявлено, поэтому гарантия монотонности ECME на него не распространяется.

Как добавить оптимизатор#

Унаследовать Optimizer и реализовать minimize. Реализация принимает начальную точку списком чисел, возвращает список той же длины, выдерживает +inf в значениях цели и не возвращает точку, где цель бесконечна. Состояние между вызовами не требуется: один экземпляр оптимизатора используется для всех блоков и итераций.

Ограничения#

  • Ограничения на параметры передаются только через +inf в цели, границы и ограничения scipy не используются.

  • Настройки scipy.optimize.minimize (число итераций, допуски) не передаются и остаются по умолчанию.

  • Результат сходимости не возвращается: остановка по лимиту итераций выглядит так же, как успешная.

  • Если оптимизатор вернёт точку, нарушающую ограничения параметризации, fit прервётся с ValueError: такой результат сейчас не перехватывается.
