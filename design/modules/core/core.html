Модуль core#

Назначение: объяснить, как устроена модель смеси MixtureModel, с которой работают все оценщики, и что модуль берёт из pysatl-core.

Состав модуля#

Публично модуль экспортирует один класс — MixtureModel. Остальные файлы приватные:

  • mixture.py — MixtureModel.

  • _components.py — функции над компонентами смеси. Только здесь код обращается к внутреннему устройству распределений pysatl-core, поэтому смена API pysatl-core затрагивает один файл.

  • _sampling.py — DeterministicSampling, стратегия сэмплирования, которая учитывает random_state.

Распределения из pysatl-core#

Своих распределений в библиотеке нет: компонента смеси — любое распределение ParametricFamilyDistribution из pysatl-core. От компоненты core использует только характеристики, которые вычисляет pysatl-core через calculate_characteristic: LPDF и PDF для плотности и правдоподобия, PPF для генерации выборки. Поэтому новое семейство или параметризация, добавленные в pysatl-core, сразу работают в pysatl-mpest без изменений кода.

Для оценки это верно с одной оговоркой. Численные стратегии M-шага — максимизация Q-функции и правдоподобия наблюдаемых данных через оптимизатор — работают для любого семейства и параметризации. От семейства зависят только специализированные стратегии, которые выбираются по паре «семейство, параметризация»:

  • аналитическое решение Q-функции зарегистрировано для Normal с параметризацией meanStd и Exponential с параметризацией rate; для остальных пар используется численный путь;

  • метод моментов реализован только для тех же двух пар; для других он бросает NotImplementedError.

Чтобы новое распределение оценивалось быстрее, для него добавляют аналитическую реализацию стратегии в estimators.iterative.

Диаграмма классов#

Лист Overview показывает классы модуля с публичными членами и классы pysatl-core и estimators, с которыми они связаны.

Исходник диаграммы классов

  • Компоненты смеси — распределения ParametricFamilyDistribution из pysatl-core. MixtureModel хранит их кортежем и не копирует.

  • DeterministicSampling наследует SamplingStrategy из pysatl-core.

  • to_core_mixture() только экспортирует смесь в FiniteMixtureDistribution из pysatl-core. MixtureModel не построена на этом классе, а внутри библиотеки метод не вызывается.

  • Оценщики estimators принимают и возвращают MixtureModel, в estimators.iterative текущую и предыдущую смесь хранит PipelineState. Приватный _components вызывают OptimizationBlock и MaximizationStep, а также приватная стратегия M-шага observed_data_likelihood, которая на листе не показана.

MixtureModel#

Неизменяемость#

Смесь нельзя изменить после создания. Методы with_component, with_components, with_log_weights, with_added_component и without_component возвращают новую смесь, исходная остаётся прежней. Поэтому смесь хешируется, copy.copy возвращает тот же объект, а PipelineState и история итераций хранят ссылки на прежние смеси без копирования.

Веса#

Смесь хранит нормализованные логарифмы весов log_weights в массиве только для чтения. Свойство weights вычисляется из них через softmax при первом обращении и кешируется.

  • Конструктор принимает обычные веса и проверяет, что их столько же, сколько компонент, что они неотрицательны и в сумме дают 1. Без весов компоненты получают равные веса. К нулевому весу перед логарифмированием прибавляется наименьшее положительное число float64, чтобы логарифм оставался конечным.

  • with_log_weights принимает любые логарифмы весов и нормализует их через log_softmax, поэтому их сумма не обязана давать 1.

  • with_added_component(component, weight) умножает прежние веса на 1 - weight, сохраняя их пропорции. weight должен лежать в интервале (0, 1).

  • without_component перенормирует оставшиеся веса. Удалить последнюю компоненту или единственную компоненту с положительным весом нельзя.

  • with_component и with_components меняют только компоненты и переиспользуют уже нормализованные веса без повторных проверок.

Вычисления#

component_lpdf_matrix(X) возвращает логарифмы плотностей всех компонент без весов: для выборки из n точек это матрица (n, n_components). Матрица — представление массива (n_components, n), поэтому значения одной компоненты лежат в памяти подряд, и свёртка по оси компонент работает в несколько раз быстрее. Этим пользуются E-шаг и стратегия правдоподобия наблюдаемых данных, которые прибавляют к матрице log_weights и берут logsumexp.

lpdf считается так же: матрица плюс log_weights, затем logsumexp по компонентам. pdf — экспонента от lpdf, loglikelihood — сумма lpdf по выборке. Точка вне носителя всех компонент даёт -inf в lpdf и, как следствие, в loglikelihood.

Генерация выборки#

Лист «Sequence: generate» показывает, как generate получает выборку и почему результат воспроизводим.

Исходник схемы генерации

generate один раз создаёт генератор rng из random_state и передаёт его во все вызовы. Сначала по весам для каждой точки выбирается компонента, затем DeterministicSampling для каждой компоненты берёт rng.random(n) — равномерные числа на [0, 1), на схеме uniform — и переводит их в выборку через квантильную функцию (PPF) компоненты. Это метод обратного преобразования. В конце выборка перемешивается тем же rng.

Стандартная стратегия сэмплирования pysatl-core игнорирует random_state, и выборку с ней нельзя воспроизвести. Поэтому generate не использует стратегию сэмплирования компоненты и всегда вызывает DeterministicSampling. Переданный в random_state объект numpy.random.Generator используется без копирования, его состояние сдвигается, так что несколько вызовов могут делить один поток случайных чисел.

Сравнение и хеш#

Сравнение == не зависит от порядка компонент. Каждая смесь сводится к отсортированному списку пар «ключ компоненты, вес», где ключ — имя семейства, имя параметризации и все параметры (_components.component_key). Веса сравниваются с допуском np.isclose, поэтому хеш строится только по компонентам: смеси, равные с учётом допуска, получают одинаковый хеш.

_components#

Функции модуля скрывают от остального кода устройство компонент pysatl-core:

  • lpdf, pdf — плотность компоненты и её логарифм; для скалярного входа результат скалярный.

  • free_parameters — свободные, то есть оптимизируемые, параметры компоненты; fixed_parameters — параметры, зафиксированные через family.view(...); all_parameters — те и другие вместе.

  • with_parameters — новая компонента с обновлёнными свободными параметрами.

  • component_key — хешируемый ключ компоненты для сравнения смесей.

Зафиксированные параметры хранятся не в компоненте, а в представлении семейства PartialParametricFamily, из которого её создали. Публичного способа получить это представление в pysatl-core нет: component.family возвращает базовое семейство из реестра. Поэтому _components берёт представление из класса параметризации компоненты.

with_parameters бросает ValueError, если имя не относится к свободным параметрам или новые значения нарушают ограничения параметризации. Стратегии M-шага считают второй случай недопустимой точкой.

Ограничения#

  • Компонента, созданная with_parameters, получает стратегии вычисления и сэмплирования по умолчанию: пользовательские стратегии исходной компоненты после M-шага не сохраняются.

  • generate не использует стратегию сэмплирования компоненты.

  • with_component и without_component не поддерживают отрицательные индексы.

  • Смеси, веса которых отличаются меньше допуска np.isclose, считаются равными.
